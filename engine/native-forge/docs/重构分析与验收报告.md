# 原生中文教材工作流：根因、重构与实测

## 已实现的结果

本次交付是可运行的 Native Forge 引擎、可调用的 native-textbook 技能、原生图重绘模块，以及四组经过来源与全部输出页检查的成果。英文 PRML 完整1.1节、Carey A/B选段、旧工作流真实扫描缓存选段均产生零位图的出版PDF。新系统不依赖Qwen API；DeepSeek负责大部分机械起草，Codex负责范围、符号、数据、图形和最终验收。

原稿9文件的SHA-256均重新核对且未改变；旧BookForge代码和旧作品没有覆盖。原生效果已在这些实际选段上复现，未把未跑完的整本书或任意扫描稿描述为已经验证。

## 为什么旧系统慢且效果差

先完整读取旧聊天的可用文字历史，再检查当前实现，避免把旧版本印象套在后来改过的代码上。原会话日志644MB，流式取出916条user/assistant文字，排除工具输出并遮蔽凭据模式；详情见 `audit/legacy/legacy_audit_verified.md`。

旧ch001的45页实际有28个PNG引用，17页用到位图。根据旧资产角色，23项归为公式回退、5项归为表格；有164个原生展示数学块，但0个tabular。前五页恰好没有位图，所以查看首页无法发现后面的问题。

主要缺陷不是ElegantBook模板，也不能简单归为Qwen“看不懂”。旧系统把页面渲染成220DPI的PNG后，用裁剪图作出版资产，再把少量通过窄规则的对象提升为原生。公式识别器偏数量金融短表达式；表格超过30行或7列就不再抽取单元格。原生文字快路径又只取文字，没有完整图表与数学结构。这使通用教材的复杂对象在输入/表示阶段失去重建机会。

更直接的证据是：旧IR中，`p000029-b0014`已经有正确形状的逆分布函数TeX，`p000036-b0014`已经有四行求和/微分推导TeX，但math_latex仍为空，后续受限识别器没有使用这些内容。对应PNG裁剪还分别出现章节引用文字、截掉右侧推导等错位问题。不能把这些错裁资产一概理解为源书确实不可转写。

慢则来自串行页面解析、串行翻译、串行公式/表格OCR，以及截图之后的逐对象修补。旧哈希、断点、递归补缺和有限重试是有用的；新系统保留其思想，替换出版主表示。旧章节的completed只取决于结构QA，允许同时存在23项待复核回退。完整全书发布另有拦截，故旧产物不能被称为已经达到原生内容验收。

## 参考工程实际怎么做

7份PDF的2549页全部做了对象统计，两个ZIP的832个成员安全解压，TeX和资源清单批量审读；代表页视觉检查与全量统计分开记录。完整证据在 `audit/references/REFERENCE_AUDIT.md`。

PRML的正文、公式、表格是语义LaTeX。313个PDF图资产中，268个不含位图、45个含位图；其正文源码没有TikZ/PGFPlots/chemfig，图主要由BookFigure嵌入。已比对图的原字体与路径支持源矢量保留这一做法。不能据此断言其未知后台从未重绘，但“截图少必定全部重绘”也不是证据支持的结论。

随机矩阵译本的25个PDF插图全部含位图，多数是高分辨率位图的PDF封装；精美主要来自文字与数学的原生重排。未取得其英文底本图像作一致性验证，因此不能确认这些位图的来源身份。Carey A的22个独特编码图像流在中英文中全部一致，PRML也有192个一致图像流，直接表明大量来源图被复用。PDF后缀、肉眼清晰或位图数量少，都不能单独证明语义重建。

因此正确复制的是元素级路由：正文/数学/表格原生；已有清晰矢量图保留；需要本地化或重新表达的图代码重绘；真实照片保留原始图像。重绘不是为了追求一个数字比例，而是使图的结构、数据和标签正确。

## 六个模块的实际合同

| 模块 | 已实现功能 | 不能代替的检查 |
|---|---|---|
| 来源证据 | 原稿哈希、选页、稳定块ID、文字/字体/位图/路径、预览缓存；扫描对象清单 | 抽到文字不等于完整结构；空扫描页不能跳过 |
| 语义翻译与重建 | 有序content.json、一次中文TeX起草、跨页段落、来源回指、排除理由、未解决项 | Codex对照源文、上下标、条件、每个表值 |
| 图形 | 真矢量裁剪、xy_plot/flowchart/TikZ/chemfig重绘、原始位图显式登记；规范/TeX/代码哈希 | 不捏造数据；裁出图不能缺图例、箭头或反应条件 |
| 排版 | 原有ElegantBook类+薄样式层、连续章节、两轮XeLaTeX、原号、原生表格/数学 | 段落、浮动体、正文与图字号、全部输出页视觉检查 |
| QA | 来源覆盖、类型、位图流与使用次数、日志、缺字/溢出/引用、输入及产物指纹 | 程序过关不等于译文正确；AI复核明确署名 |
| 恢复/发布 | 缓存、独立chunk、合并前验证、失败保留旧稿、过期复核拦截、PDF/TeX/证据包 | 仅当前范围的完整语义和视觉复核可以发布 |

详细格式见 `design.md`、`worker-contract.md`、`large-book.md`。扫描页必须逐对象登记，源哈希不一致、对象未覆盖或空清单都阻止构建。图片不能作为公式或表格的静默回退。

## 重绘模块的实际验证

模块由Python生成绘图TeX，再编译成真矢量PDF；同时保存规范、绘图源和来源记录。真实编译已经验证曲线图、中文流程图和chemfig化学结构，均为0位图。通用图用来源结构决定节点/边，数值图用来源数据或明确精度的数字化数据，其他数学函数可先产生可审计的坐标点再绘制。

本次PRML图1.2确实重新生成：从原矢量圆点提取10个观测坐标，用原生坐标轴校准，按4位小数记录；最大舍入误差0.00004884。绿色曲线由原式sin(2πx)在[0,1]生成201个点，没有重新抽样随机噪声。新图有中文图例，绘图规范和TeX与成品一同交付。其余6图保留源矢量，防止为了“重绘”而损伤已有正确图形。

## 效率与可靠性的真实边界

本次9页证据准备一次约0.8秒，双轮PRML编译约8.6秒，原生曲线重绘约6.9秒，QA约0.6秒。这些是本机样段阶段的观测，不是同源旧新全流程速度对照；API起草和监工检查仍占主要时间，磁盘和服务延迟会变化。原旧书PDF已不在旧记录路径，只能用完整页缓存作独立扫描验证，不能声称已经重新跑完旧整章或测得整书加速倍数。

新系统节省的是重复处理和后期补截图的工作量：证据一次缓存，中文与TeX同一语义起草，图形资源只做一次，小节独立恢复，编译无需模型调用，失败只修具体块。仍需阅读和校对，不把“无需监工”当作稳定产品的假设。

本次确认可编译交付TeX：直接调用XeLaTeX两轮通过，没有借助引擎或API。单独编译的PDF字节可能因元数据/构建环境不同而改变；发布保留原复核文件及哈希，不能把编译成功误报成跨环境字节一致。
