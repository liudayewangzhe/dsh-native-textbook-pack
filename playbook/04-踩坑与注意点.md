# 04 踩坑与注意点

> 每条按 **症状 → 根因 → 判据/命令 → 怎么避免** 写。括号里是证据出处（会话文件或参考文件）。
> 数字全部来自实测记录，不做估算。

---

## A. 单位与字号

### A1 整册字号被乘 72/96（缩小 25%）

| | |
|---|---|
| **症状** | 整页发空、正文明显偏小；与源并排看像"被缩过" |
| **根因** | 把 PDF 抽取出的字号当 CSS px 处理，乘了 `72/96`。生成层 bug，**不是预览器问题** |
| **判据** | `compare_typography.py` 的 `body_scale_ratio` ≈ **0.75**；逐级约 −25%；行距**没有**同比缩小，行距比从 1.63 恶化到 **2.00** |
| **实测数字** | 失败稿正文 **7.51 pt**（合格 9.46）、标题 **10.69 pt**（合格 14.15）、字号种类 **30 种**（合格 **8 种**）；旧构建里 `PT_PER_PT = 72/96` 把标题 14.346→10.687、正文 9.963→7.512 |
| **怎么避免** | 铁律：**PDF 抽取的 span 字号就是 pt，不乘 72/96**（`mm = pt × 25.4/72`）；每次交付前跑 `compare_typography.py` 当门禁 |

出处：`skills\native-textbook\references\chinese-typography.md`、`cover-and-geometry.md` §4–5、`upgrade-notes-20261014.md`；`sessions\09-native-textbook技能升级.md`。

> **附带诊断指标**："字号种类数"是极强的信号。合格 15 页课件只用 **8 种**字号；失败稿用 **30 种**——种类翻几倍通常意味着内容被"逐帧缩放到框里"（fit-to-frame），而不是按统一阶梯排版。用 `check_typography.py` 的"字号直方图"看这一项。

### A2 声明值 ≠ 实测值

| | |
|---|---|
| **症状** | "我按模板参数设了字号"，但成品与源并排就是不一样 |
| **根因** | 模板里写的字号/行距与最终 PDF 实际渲染不一致。原因不止一个：CJK 字面率、`\fontsize`+`\selectfont`、`\linespread`/`\baselineskip` 交互、数学字体自带尺寸、`setspace` 类宏 |
| **实测数字** | 封面声明 16 pt → 实测 **14.94**（−6.6%）；正文声明 9.5 → 中文 **9.46**、同页数学 **9.96**；行距声明 13.3 → **15.6–15.9**（+17%~+20%）；课件源正文行距 ≈13.8 pt → 成品比源松约 **13%** |
| **判据/命令** | 从**源**抽目标字号清单 → 从**实际交付 PDF** 抽 `(字号, 文本)` → 逐条比对，偏差 **>±3%** 先查因 |
| **怎么避免** | 把"回抽实测比对"写成硬门禁；报告里写实测值，**不写"模板参数已设置"**。注意**中文与数学的实测字号常常差约 5% 是正常的**（字体字面高度不同），别为了"对齐"去改其中一个 |

出处：`cover-and-geometry.md` §4、`references/workflow-gates.md` §8（`size_check` 字段）。

## B. 内容完整性（扫描件/OCR 最容易死的地方）

### B1 只读了半页（`band0` 读完就停）

| | |
|---|---|
| **症状** | 页面上半部正常，下半部整段内容缺失；交付 PDF 里看不出"缺了"，因为它是**连续**的 |
| **根因** | 分带图 `pNNNN_b0.png`（上半页）读完，**没有把 `b1`（下半页）读到页脚** |
| **本项目实证** | **8 次证实**：p0193 / p0215 / p0220 / p0230 / p0007 / p0251 / p0263 / p0217。其中 p0230：objects y 上界只到 **0.543**，页面墨迹到 **0.881**，gap **0.338**（最大）；p0263 分片覆盖到 y≈0.752 就停，页脚对象在 0.939 |
| **判据/命令** | `scan_repair\detect_partial_pages.py --threshold 0.12`；**汇报必须分别给出「正文对象 y 上界」与「含页脚 y 上界」** |
| **怎么避免** | 任务单里写死："务必把每页的 b1 读完到页脚；objects 的 y 上界应 ≥ 0.88"。**注意 0.88 这个阈值会被页脚对象伪造**——p0263 的 worker 报了 `y_max=0.949`，那其实是**页脚对象**的坐标，它并没读到例题框。所以判据要看**正文**对象的 y 上界，或干脆对比页面墨迹 |

出处：`references/scanned-source-repair.md`、`references/stopping-point-example.md`（铁律 §2）、`sessions\10-计算物理-扫描件主控.md`（p0230、p0263 两处）。

### B2 半页漏读的**另一种**表现：状态判断错

| | |
|---|---|
| **症状** | 整页上半部被跳过 |
| **根因** | worker 把本页首段误判为"上一页的续文"。p0062 的前一页是**红色章扉页**（本无正文），于是 p0062 整页上半部（5 段 + 公式 (3.0.1)(3.0.2)）被视为"承接上文"而整块跳过 |
| **判据** | 编号连续性检查首先暴露它（§3.0 只有 3,4,5） |
| **怎么避免** | 任务单写："**不要把本页顶部的内容当成上一页的续文而跳过**；只有当你确实在本页分带图里看到该段落的文字时才转写它" |

出处：`sessions\10-计算物理-扫描件主控.md`（p0062 补录）。

### B3 相邻页内容串位

| | |
|---|---|
| **症状** | 两页内容整体错位；合并后正文重复并从中间断段 |
| **根因** | worker 把相邻页内容收进本页（p0032 下半部两段被写进 p0033 的分片） |
| **判据** | 墨迹行覆盖审计（`audit_coverage.py`）：p0048 下半部 18 行无任何对象覆盖 |
| **怎么避免** | 任务单写："不要收相邻页内容"；每批**必须**跑覆盖审计；发现后**双向迁回 + 补录**，并核对原书实测行位置 |

### B4 `inbox` 分片才是唯一事实源

| | |
|---|---|
| **症状** | 修完 `source_inventory.json`，下一次合并内容又变回去了 |
| **根因** | `merge` 会用分片**重新物化** `source_inventory.json` 与 `content.json` |
| **怎么避免** | **修复必须落在 `inbox/pNNNN.json` 分片上**。历史上有多个 worker 因直接改 `source_inventory.json` 白干过一轮（`references/scanned-source-repair.md` §3 铁律 1） |

### B5 一个池子里两个 worker 写同一页

| | |
|---|---|
| **症状** | 内容静默丢失（后者覆盖前者） |
| **根因** | 重复派单 |
| **实测** | 已发生 **6 次**重复派单导致的覆盖冲突 |
| **怎么避免** | 维护派单台账（DISPATCH-LEDGER），**一页只派一个 worker**；共享 `content.json` / `assets.json` / 模板**不并发修改**（`engine\native-forge\AGENTS.md`、`docs\large-book.md`） |

## C. 图形

### C1 坐标系方向靠直觉 → 连续三轮返工

| | |
|---|---|
| **症状** | "标签飘着""本应在上面却跑到下面""a 的位置不对" |
| **根因** | 手写坐标系的 **y 方向判断反了**。模板用 `y=-1mm` + 左上原点时，**y 增大 = 页面向下**，与 PDF pt 坐标系相反 |
| **判据** | 画 `y=10 / y=50 / y=90` **三条线**，渲染后确认哪条在页顶——**先做这个 3 行实验再排版** |
| **检查器的盲区** | `check_typography.py` 只看渲染结果，**发现不了"方向搞反"** |
| **怎么避免** | 记法：`y` = 从纸顶往下的毫米数；想放"页面上方"就用**小** y |

出处：`references/slide-pitfalls.md` §A1（"这条单独占一节，因为它在实测中连续造成 3 轮返工"）。

### C2 图 bbox 含印刷图题

| | |
|---|---|
| **症状** | 裁出的资产图片里带着一行印刷的"图 X.Y 说明文字"；成品里图题重复出现 |
| **根因** | 两处叠加：(a) 登记 `figures[].bbox` 时把图体 + 印刷图题一起框进去，`make_assets.py` 照 bbox 裁；(b) worker 分片里**同时**保留了 caption 段落块和 figure 块的 `caption` 字段，引擎会自动输出 figure caption → 印两遍 |
| **判据** | 裁出图先看再登记；`references\scanned-source-repair.md` §1 明确"图 bbox 不含印刷图题" |
| **怎么避免** | bbox **只含图体**（图题由 `\caption` 输出）；合并前跑一道 `cleanup_caption_blocks.py` 一类的工序，消掉重复的 caption 段落块，并把它的证据 ID 折进 figure 块 |

出处：`sessions\10-计算物理-扫描件主控.md`（p0029/p0031/p0034 图题同文两处、`cleanup_caption_blocks.py`、修 p0212/p0213 的图 bbox）。

### C3 位图冒充矢量 / 矢量冒充位图

| | |
|---|---|
| **症状** | 报告里写"全部波形已矢量重绘"，实际是嵌入位图 |
| **根因** | 只看容器格式（`.svg`/`.pdf` 后缀）或 `get_images()` 为空就下结论。**`get_images()` 为空不证明页面是矢量**；把 PNG 包进 SVG 也不转成矢量；shading 可能被渲染器报成运行时图像 |
| **实测** | Signals 原稿的正弦曲线**本身就是嵌入 PNG**，旧稿误称"全部波形矢量"；失败稿第 5 页的正弦曲线是 **179×134 px 位图重复 5 次**（由源 891×667 重采样） |
| **怎么避免** | 检查**实际可见 image occurrences** 与资产职责；asset 的 `--kind` 如实选（`vector_pdf` / `source_raster` / `source_pdf` / `page_raster`）；示意波形可用解析定义原生重绘，**真实照片按来源登记**，不捏造 |

出处：`references/slide-native-pdf.md`、`references\layout-and-polish.md`（渐变/shading 的原生判定）。

### C4 公式/表格截图回退

| | |
|---|---|
| **症状** | 成品里公式是图片，不可搜索、不可编辑 |
| **根因** | 遇到难写的公式就截图兜底 |
| **判据** | 引擎判 `forbidden macro '\includegraphics'`；`figure must not carry tex` |
| **怎么避免** | 公式、表格**必须原生 TeX**；`figure` 块不写 `tex`；`kind="table"` 的块**必须自带** `\renewcommand{\thetable}{...}` + `\caption{...}`（引擎对 table 块**原样输出**，不会替你写表号表题——少了这两样，成品里既没有表号也没有表题，而表体还在，**很难一眼看出**） |

出处：`references\scanned-source-repair.md` §2、§5。

### C5 图内标注"飘着"、度量线未落轴、轴穿字

| | |
|---|---|
| **症状** | "这个 a 跟 2π/ω 还有箭头就空中飘着干嘛呢""竖向虚线没有往下延伸到横轴，竖向长度不明确""坐标轴都穿数字 0 而过" |
| **根因** | 标注只放在"看起来空的地方"，没有引线、也不在所指对象邻近；度量线的两端没有落到基准轴；轴上数字用**居中**锚点放，轴就从字形中间穿过 |
| **判据** | ① 引线连到所指对象的**特征点**（如波峰而非波谷）／② 紧邻对象／③ 跨距标注两端落在被跨的两个特征点上。轴上数字一律**锚在轴的一侧**（`anchor=west` / `anchor=east`） |
| **检查器的盲区** | `check_typography.py` 的 `text_obscured_by_fill` 覆盖不到"线穿字"；`text_overlap` 只在重叠面积够大时才报，**擦线容易漏** |
| **怎么避免** | 放大 5–7 倍看图逐条自问"这个标注指着什么？这个数字能不能对着一条轴直接读出来？" |

出处：`references\slide-pitfalls.md` §A2/A3/A4、§C1/C2。

### C6 长句折行压字（手写坐标课件的头号缺陷）

| | |
|---|---|
| **症状** | "这条文字和上一条叠在一起了" |
| **根因** | 手写坐标里文本的垂直占位 = **行数 × 行距**，而人不会每次去数行数 |
| **判据** | 单行间距 ≥ **1.0 行距**；**两行项之后**的间距 ≥ **2.2 行距**。不要凭感觉写 8.5mm 就当够了 |
| **命令** | `check_slide_spacing.py --tex ... --min-gap-ratio 0.90` |
| **血的教训** | 该检查器**第一版判据取 0.75**，等于允许相邻项重叠 25% 行盒，**放过了真实缺陷**；而且本轮"逐页看过全部 15 页"**仍漏掉 4 处**（长句折行重叠、空节点、标签擦线、度量线未落轴） |

出处：`references\slide-pitfalls.md` §B1、§D2/D3。

## D. 门禁与"以为做完了"

### D1 三种"通过"互相替代

| | |
|---|---|
| **症状** | "编译成功""检查脚本通过""模型说看过"被当成验收 |
| **根因** | 把中间环节的成功当成最终产品的成功 |
| **反例（实测）** | 未转义的 `%` 让半页正文**静默消失而编译成功**；`nullfont` 让字形消失而退出码为 0；TeX 源码正确但分母在渲染时被裁掉 |
| **怎么避免** | 记住证明边界（`references\workflow-gates.md` §1）：**编译成功只证明没有致命错误；`technical_pass=true` 仍禁止交付**。越界引用检查结论（例如用"文字可提取"证明数学正确）**视为造假** |

### D2 检查器没有负向回归 = 没有检查器

| | |
|---|---|
| **症状** | 检查说通过，成品还是坏的 |
| **根因** | 一个"永远通过"的检查器等于没有。**"通过"的含义完全取决于配置里放了多少真实约束** |
| **实测对照** | 同一份旧差稿：给**项目内容合同**时报 **5 项失败**；只给**基础配置**时 **0 issues 通过** |
| **怎么避免** | 任何新增/修改的检查器，必须用**已知有缺陷的产物**证明它会失败，并记录**实际退出码**；还要用"配置错误"的输入（越界页码、负页数、不存在的必需字符、错误 bbox）证明它以"配置错误"退出而不是静默通过。回归证据写进维护记录，不是口头确认 |

出处：`references\workflow-gates.md` §3、`references\slide-pitfalls.md` §D2。

### D3 "我逐页看过了"不是证据

| | |
|---|---|
| **症状** | 视觉审核记录写"全部页 checked"，实际缺陷仍在 |
| **怎么避免** | 视觉审核是**两级**的：L1 接触表（每张 6 页，看**全部**输出页）+ L2 高风险页高倍（PyMuPDF `Matrix(3,3)` ≈216 dpi 与 Poppler 144 dpi **两种渲染器都用**）。审查记录必须绑定**当前交付 PDF 的 `pdf_sha256`**，逐**对象**列出"查了什么"，并写 `limits`。**没有实际看图只能报 `not_performed`**；worker 不得预填 "pass"；制作人不得替审查者签字 |
| **顺带** | 新 hash 使旧复核**全部失效**；只有**像素完全一致**的页才能继承旧审查（逐页比较渲染后的 `.samples` 字节相等并记录继承自哪个哈希） |

出处：`references\visual-audit.md`、`references\workflow-gates.md` §1。

## E. 组织与资源

### E1 worker 的上下文：给太多和给太少都错

| | |
|---|---|
| **给太多** | 把全书所有 PNG、长日志反复发给 worker；它会把上下文耗在无关页上。**每批 3 页为宜；5 页时长与上下文都逼近上限，失败率显著上升**（`references\scanned-source-repair.md` §4） |
| **给太少** | 任务单缺来源范围、写入路径、允许修改的对象 → worker 只能猜。合同层缺陷的典型：技能只给路由不给出渲染方法与终稿门禁，worker 就自行补一条不可靠的转换链 |
| **正确姿势** | 计划和通用规则由监工保持**一份**；worker 只收与当前块相关的部分。任务单要填**真实路径与范围**，不能只复制通用清单。模板见 `06-示例用法.md` |

### E2 内存 < 1 GiB 仍跑重活

| | |
|---|---|
| **症状** | 构建/前检中途自保护中止（`physical memory below 1.00 GiB (0.648 GiB); checkpoint preserved`），或"改了十几分钟 PDF 不动"的静默失败 |
| **实测** | 8 worker + XeLaTeX 抢内存，可用 **1023 MiB 差 1 MiB** 被引擎 halt |
| **怎么避免** | 测量 → 低于门槛**暂停**重活 → 只做**非破坏性回收**（白名单进程 `EmptyWorkingSet`，不杀进程）→ 复测 → 恢复后**串行**继续。保留名单：harness/agent、编辑器与终端、VPN、SSH、安全软件、输入法、系统进程。**禁止**为过 preflight 降低阈值，**禁止把降低后的阈值下发 worker**（历史事故：向 worker 传 `NF_RAM_FLOOR_MIB=560`）。`NF_RAM_FLOOR_MIB` 的合法范围与张力见 `02-环境与依赖.md` §6 |
| **配套** | 用 `run_build_loop.py --rounds N` 之类的**闭环**驱动，让"修复→准备→合并→出图→合并→编译"自动重试；这是把静默失败变成可见失败的关键一步 |

出处：`references\workflow-gates.md` §6、`references\stopping-point-example.md`、`sessions\10-计算物理-扫描件主控.md`、`sessions\05-经典力学-主控.md`。

### E3 Windows 沙箱权限报错

| | |
|---|---|
| **症状** | 任何 shell 命令都返回 `Error: sandbox-local windows-acl temp grant materialization failed and its cleanup also failed`（读文件正常，只有 shell 挂） |
| **根因** | Windows 沙箱无法在工作区上建立临时授权。**这不是脚本或内容的问题** |
| **处置** | 加载并执行 `diagnose-windows-sandbox-acl` 技能：它**一条命令**同时诊断并修复（检查路径及每个上级目录，补当前用户缺少的完全控制项、移除外来的应用包权限项），并在同一轮搜索子树。判据看它最后的 `RECAP` 与 `details.nextAction`：`verify_original_confined_operation` = 修好了，去重跑原操作；`stop` = 没修任何东西，如实报告并停 |
| **不要做** | 不要手工改权限、不要提权（UAC/`runas`）、不要重复执行被拒的命令 |
| **相邻坑** | 报"**在此系统上禁止运行脚本**"是 **Execution Policy**，与沙箱无关。用 `.cmd` 包装 `-NoProfile -ExecutionPolicy Bypass -File`，或在本进程内 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force` |
| **实测** | 本机该报错出现过两次（启动阶段与失败排查阶段），都由该技能处置；有一次脚本判定为 `NOT_THIS_CLASS`（没有需要修的权限项），此时**按脚本的 `nextAction` 停手**，不要自己加戏 |

## F. 几个只踩过才知道的 LaTeX/契约细节

| 症状 | 根因 | 处置 |
|---|---|---|
| 图题解析失控（`File ended while scanning use of \caption@ydblarg`） | 正文里的 `20%` **没有转义**，LaTeX 把 `%` 当注释，吞掉了后面的花括号 | 发布前加一道清洗：扫描未转义的 `%` 并转义/修正（`sessions\01-…md`） |
| 表 1.3.1 的表题留在上一页、整表跳到下一页，留下近空白页 | 用普通 `tabular`/浮动 `table` | 改 `longtable`（跨页自动重复表头）；一个被两个分片拆开的表要合并成一个 longtable，否则浮动体顺序错乱 |
| 编译崩：`! Missing $ inserted` | 替换 `⋯` 时把 `\cdots` 放进了**文本模式** | `fix_cdots.py`（跨行状态机，只包文本模式处） |
| 编译崩：`\begin{equation}\begin{equation*}` / `\end{equation*}\tag{...}\end{equation}` | 环境嵌套。`\tag` 与环境嵌套是 LaTeX 最脆弱的一环 | 每 equation 块**恰好一个 `\tag`**；带 `\tag` 必 `numbered:true`；原书**无编号**的显示式**不加 `\tag`**。修结构后**立即重编译验证**——第一版清理脚本方向选反，把编译从 36 页推到 26 页 |
| 罗马数字 Ⅰ Ⅱ Ⅲ / 𝜇 缺字形 | 正文字体无 U+2160–217F 字形；`\mathrm{\mu}` 把 μ 交给正文字体 | preamble 加 `\xeCJKDeclareCharClass{CJK}{"2160 -> "217F}`；改写 `\mu\mathrm{m}` |
| 红底白字页被判"整片无墨迹" | 常规"RGB 三通道 < 150"判墨对白字是**漏检** | 红底白字改用「**R>100 且 G>100**」定位；红底上的黑字仍用三通道 < 150 |
| b1 分带图偏移是"固定值" | 各页偏移不同（实测在 726–739 之间） | **用两带重叠区逐像素比对确认**（二值掩码 IoU 最硬），不要照抄别页的偏移量 |
| 页脚被建成 block | `header_footer` **不是合法 block kind** | 页脚只作 object + `excluded_objects`，绝不建 block |
| 引擎自己也不报的"隐形"排版缺陷 | 成熟成品也有：近空白页（孤儿行）、同一推导被分页切断（实测 28 处相邻页以公式行结束/开始）、上下标注号压到前一个字 | 这些只能靠**看图**抓；调 `\widowpenalty`/`\clubpenalty`/`displaywidowpenalty`，或改写该段 |

## G. 归因：不要把所有问题都归到同一层

同一个症状可能来自**四层**，归错层会导致错误修复（`references\workflow-gates.md` §5）：

| 层 | 例子 | 处理 |
|---|---|---|
| 工具层 | 原生 PPTX 预览把内容放大约 1.5 倍（最小 5 矩形用例可复现）；同一 CLI 的 PDFium 分支正常 | 先最小复现隔离；换用真实导出的 PDF 独立渲染验证；**不要为迁就坏预览而缩放内容** |
| 生成层 | PDF pt 被乘 72/96；分式分母盒超出 viewBox；图区 bbox 裁掉曲线；展开式漏项 | 修生成逻辑；保持物理单位与完整对象边界 |
| 合同层 | 技能只给路由不给出渲染方法与终稿门禁，worker 自行补不可靠转换链 | 补可执行合同与门禁 |
| 监督层 | 明知图/数学损坏仍降低接受标准；整体错位先猜"缓存"；绕过资源门槛 | 隔离反馈工具；整体错位先最小复现；保留硬门槛 |

**工具缺陷与文档缺陷可以并存**：修好其中一个不会自动修好另一个。不能把所有问题归为"缓存"或"预览器"，**也不能用工具 bug 掩盖自己的生成缺陷**。
