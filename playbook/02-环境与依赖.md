# 02 环境与依赖

> 目标：在一台**新的 Windows 机器**上把这条流水线跑起来，并能用一条命令证明"环境是好的"，而不是等到编译到一半才发现缺东西。
> 约定：`$NF` = 引擎目录（含 `nf.cmd`）；`$SK` = 技能目录（`native-textbook` 的安装位置）；`$PY` = 带 PyMuPDF 的 Python；`$SRC` = 原稿 PDF；`$PROJ` = 项目目录。

---

## 1. 依赖清单

| 组件 | 版本要求 | 用途 | 缺了会怎样 |
|---|---|---|---|
| Agent 运行环境（DSH / Codex / 其它能加载 skill 的 harness） | — | 加载 `native-textbook` skill、跑 worker | 只能手工执行命令，没有 worker 并行 |
| 本包 `skills\` | 随包 | `native-textbook` 及其参考文件、检查脚本 | 没有合同与门禁，等于裸做 |
| Native Forge 引擎 `$NF` | 随包 | `prepare/asset/redraw/build/qa/release` | 没有组装、构建、发布门 |
| Python | **3.10+**；实测 3.12.14 | 引擎与全部脚本 | 引擎不启动 |
| PyMuPDF (`fitz`) | 实测 1.28.0 | 页面渲染、文本/图形抽取、字号回抽 | `doctor` 报 `pymupdf.available=false`，`ok=false` |
| numpy | 随运行环境 | 扫描件修复脚本（像素/墨迹分析） | 覆盖审计、部分修复脚本失败 |
| XeLaTeX（TeX Live） | 实测 TeX Live 2024 | 构建 PDF | `doctor` 报 `xelatex.found=false` |
| 中文字体 | SimSun / SimHei / KaiTi；课件常用 Microsoft YaHei | 正文、标题、强调 | 字符缺字形（见 §5） |
| Poppler `pdftoppm` | 可选 | **第二渲染器**交叉核对 | `render_review_sheets.py` 的 Poppler 分支跳过并记录（**不伪造**） |
| LibreOffice | 可选 | 只在需要 pptx / docx 交付时 | slide→PDF 目标不需要它 |

来源：`engine\native-forge\README.md`、`engine\native-forge\engine\native_forge.py`（`RAM_MINIMUM`、`XELATEX_LEGACY`、`resolve_xelatex`）、`skills\native-textbook\references\upgrade-notes-20261014.md`。

## 2. 用一条命令验证环境

引擎自带 `doctor`，它输出 JSON 并**以退出码表达结论**（`ok=true` → 0，否则 1）：

```powershell
& "$NF\nf.cmd" doctor
# 只看结论
& "$NF\nf.cmd" doctor | ConvertFrom-Json | Select-Object ok
# 看细节
$r = & "$NF\nf.cmd" doctor | ConvertFrom-Json
$r.pymupdf, $r.xelatex, $r.memory, $r.templates
```

`doctor` 实际检查四件事（`native_forge.py` ~2280 行）：`pymupdf`（含 `clip_to_rect` 能力）、`xelatex`（含历史路径回退）、`memory`（空闲物理内存 ≥ 1 GiB）、`templates`（模板目录与文件哈希）。**四者全绿 `ok` 才为 true。**

单独补验（`doctor` 不覆盖的部分）：

```powershell
# PyMuPDF 与版本
& $PY -c "import fitz; print('pymupdf', fitz.__doc__)"
# numpy（扫描件修复脚本要用）
& $PY -c "import numpy; print('numpy', numpy.__version__)"
# XeLaTeX
xelatex --version | Select-Object -First 1
# 第二渲染器（可选）
pdftoppm -v
```

> **历史经验**：`doctor` 报 `ok=false` 时先看是哪一项。`sessions\05-经典力学-主控.md` 里 `doctor` 报空闲内存 836 MiB（低于 1 GiB 咨询线），后续 `preflight` 真的因 0.648 GiB 自保护中止——**这个告警不是噪声**。

## 3. skill 的发现顺序（决定它能不能被加载）

从父会话继承的结论，必须记牢：

| 优先级 | 位置 |
|---|---|
| 100 | `<项目>/.dsh/skills` |
| 200 | `<项目>/.agents/skills` |
| 300 | custom（部署自定义） |
| 400 | `~/.dsh/skills` |
| 500 | `~/.agents/skills` |
| 600 | bundled（随 harness 打包） |

两条硬约束：

1. **目录形态必须是 `<name>/SKILL.md`**；**嵌套目录不会被发现**（`skills/foo/bar/SKILL.md` 无效）。
2. 同名时按上表优先级取**最高**的那一份。`未验证`：这是从"优先级 = rank 数字"直接推出的结论；12 个会话里**没有**出现过同名冲突的实测案例，我也没有读到冲突场景的记录。

本机历史做法（`sessions\02-把Codex技能接入DSH.md`）：把 Codex 的 skill 目录**以 junction/link 的方式**接到 `~/.dsh/skills/<name>`，因此一份 skill 同时被两个 harness 使用，不存在两份会漂移的副本（`upgrade-notes-20261014.md` 末段明确写了这一点）。

**换机器时的检查**：

```powershell
# 确认 skill 可见（按发现顺序查）
foreach ($p in @("$PWD\.dsh\skills","$PWD\.agents\skills","$env:USERPROFILE\.dsh\skills","$env:USERPROFILE\.agents\skills")) {
  if (Test-Path $p) { Get-ChildItem $p -Directory | Select-Object @{n='Root';e={$p}}, Name }
}
# 确认 bundle 形态正确（必须直接是 <name>\SKILL.md）
Test-Path "$env:USERPROFILE\.dsh\skills\native-textbook\SKILL.md"
```

如果 agent 的技能列表没刷新，**直接让它读那份 `SKILL.md` 绝对路径**（`README.md` 与 `PACKAGE.md` 都给了这个兜底办法）。

## 4. 引擎入口 `nf.cmd` 与本机绑定的路径（**迁移时必改**）

引擎根目录的 `nf.cmd` 里写死了 Python 解释器路径，并在启动前设好 UTF-8：

```bat
@echo off
setlocal
set "NF_PY=<某个已安装的 Python 解释器>\python.exe"
if not exist "%NF_PY%" ( echo Bundled Python runtime unavailable & exit /b 2 )
set "PYTHONUTF8=1"
set "PYTHONIOENCODING=utf-8"
"%NF_PY%" "%~dp0engine\native_forge.py" %*
exit /b %ERRORLEVEL%
```

技能侧还有一层**可移植的转发器** `$SK\scripts\nf.cmd`：

```bat
@echo off
setlocal
if not defined NATIVE_FORGE_HOME set "NATIVE_FORGE_HOME=<引擎默认目录>"
if not exist "%NATIVE_FORGE_HOME%\nf.cmd" ( echo Set NATIVE_FORGE_HOME to the engine directory. & exit /b 2 )
call "%NATIVE_FORGE_HOME%\nf.cmd" %*
exit /b %ERRORLEVEL%
```

因此换机器要做两件事：

1. 把**引擎根目录**的 `nf.cmd` 里 `NF_PY` 改成新机器上带 PyMuPDF 的解释器；
2. 设 `NATIVE_FORGE_HOME` 指向引擎目录（**推荐**，比改 `$SK\scripts\nf.cmd` 里的默认值更好）：

```powershell
$env:NATIVE_FORGE_HOME = "$NF"
& "$SK\scripts\nf.cmd" doctor
```

同理，`native_forge.py` 里还有一个 **XeLaTeX 历史路径回退**（`XELATEX_LEGACY`）：PATH 上找不到 `xelatex` 时才会用这个写死的路径。换机器时若 `xelatex` 不在 PATH，`doctor` 会报 `xelatex.found=false`，此时要么加 PATH，要么改这个常量。安装器 `install.ps1` 会在安装时把技能文档里的 `C:\Users\ltllt\...` 和 `E:\PDF\_ZH\native-forge` 改写成目标机器的真实路径；`XELATEX_LEGACY` 已改为可选环境变量 `NF_XELATEX_LEGACY`（不设置就不使用任何写死路径）。

其它本机绑定（引擎内其它文件，同样需要在迁移时改）：

- `skills\native-textbook\scripts\scan_repair\*.py` 顶部有 `INBOX` 与 `PROJECT` 两个常量，`make_assets.py`/`merge_workers.py` 另有 `assets.json`/`project.json` 路径。`references/scanned-source-repair.md` §6 明确："换一个项目时改这两处即可"。
- 各类项目级驱动脚本（`run_pipeline.py`、`run_build_loop.py`、`pipeline.py` 等）都把 `$PROJ` 与 `$NF` 写在文件顶部。

## 5. Windows 上的路径与编码注意点

| 坑 | 现象 | 做法 |
|---|---|---|
| 控制台编码 | 中文输出乱码，看不出真实内容 | 每个会话/脚本开头：`$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"`；PowerShell 里 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` |
| **BOM** | `preflight_pdf.py` 读 `inputs.json` 失败（JSON 带 BOM） | 不要用 Windows PowerShell 5.1 的 `Set-Content -Encoding UTF8` 写 JSON；**用 Python 写**（`pathlib.write_text(..., encoding="utf-8")`）。`sessions\05-经典力学-主控.md` 就是踩了这个坑后用 Python 重写清单解决的 |
| JSON 里的 LaTeX 单反斜杠 | `json.load` 直接失败 | 用 `scan_repair\fix_bad_json.py`；**逐字符扫描，别用简单正则**（会破坏合法的 `\\`） |
| 执行策略（Execution Policy） | `& 'xxx.ps1'` 报"在此系统上禁止运行脚本" | 这是本机默认策略，不是沙箱问题。用 `.cmd` 包装一层（`-NoProfile -ExecutionPolicy Bypass -File`）——本机 `link-codex-skill.cmd`、`diagnose-windows-sandbox-acl` 都这么做；或在当前进程内临时放行 |
| 长参数里的引号 | 路径含空格/中文时命令被截断 | 一律用单引号或双引号整体包住；`--bbox` 传 4 个数字不要加逗号 |
| 路径分隔符 | 混用 `/` 与 `\` | `nf.cmd` 与引擎接受两种；**写进 JSON 的路径用 `\\` 或 `/`**，别写单个 `\` |

`ExecutionPolicy` 的正确用法（本机实测有效）：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& '.\some-script.ps1' -Path '...'
# 或者不动策略，直接绕过：
pwsh -NoProfile -ExecutionPolicy Bypass -File '.\some-script.ps1' -Path '...'
```

## 6. 内存门槛（1 GiB）与 `NF_RAM_FLOOR_MIB`

重活（编译、渲染、OCR、大批量解压）在内存紧张时会中断，导致失败重跑与产物不一致。

```powershell
# 测量空闲物理内存（GiB）
$os = Get-CimInstance Win32_OperatingSystem
[math]::Round($os.FreePhysicalMemory / 1MB, 3)
```

- **默认门槛**：`RAM_MINIMUM = 1 GiB`。
- **可选覆盖**：引擎支持 `NF_RAM_FLOOR_MIB`（`configured_ram_minimum()`），取值范围被**夹在 512 MiB 与默认 1 GiB 之间**，永远不会低于 512 MiB、也不会高于默认值；低于该值仍然中止重活。引擎测试里有 `test_ram_floor_override_is_clamped` 覆盖这个夹取行为（`sessions\05-经典力学-主控.md` 记录了它的引入）。
- **技能文档的红线**：`references/workflow-gates.md` §6 写的是"**禁止**为通过 preflight 而修改/降低阈值；**禁止把降低后的阈值下发 worker**"，并点名历史事故是向 worker 传了 `NF_RAM_FLOOR_MIB=560`。

⚠️ **这两者存在张力，请注意**：`sessions\08-worker加监工模式.md` 的任务单里确实写了"若报内存不足，设 `NF_RAM_FLOOR_MIB=560` 后重试"，`sessions\10-计算物理-扫描件主控.md` 长期用 `NF_RAM_FLOOR_MIB=550` 跑闭环构建。也就是说**实践与本机技能文档的条款不一致**。本手册的建议是：

- 有 1 GiB 以上可用内存时，**不要设这个变量**，按默认门槛跑；
- 确实需要放宽时，**只在监工自己的构建命令上设**，并在台账里记明原因；**不要把放宽后的阈值写进 worker 任务单**（这正是文档点名的历史事故）。

内存紧张时的正确反应（`workflow-gates.md` §6）：

- 只做**非破坏性回收**（对白名单进程 `EmptyWorkingSet`，不杀进程）；
- 保留名单：当前 harness/agent 进程、编辑器与终端、VPN、SSH、安全软件、输入法、系统进程；
- 回收后复测；恢复后**串行**继续，不并发重跑；
- 不得把"回收成功"当作质量改进指标。

## 7. 一台新机器的上手顺序（照抄即可）

```powershell
# 0) 约定
$NF   = '<引擎目录>'          # 含 nf.cmd
$SK   = '<技能目录>\native-textbook'
$PY   = '<带 PyMuPDF 的 python.exe>'
$SRC  = '<原稿.pdf>'
$PROJ = '<项目目录>'

# 1) 环境自检（必须 ok=true）
$env:NATIVE_FORGE_HOME = $NF
& "$SK\scripts\nf.cmd" doctor | ConvertFrom-Json | Select-Object ok

# 2) 技能可见性
Test-Path "$SK\SKILL.md"

# 3) 只读前检（不改原稿、不 OCR）
'[{"id":"source-a","path":"' + ($SRC -replace '\\','/') + '"}]' |
  Set-Content -Path "$NF\reports\inputs.json" -Encoding utf8   # 若报 BOM 错误，改用 Python 写
& $PY "$NF\scripts\preflight_pdf.py" --manifest "$NF\reports\inputs.json" --out "$NF\reports\source-preflight"

# 4) 项目初始化（示例范围）
& "$NF\nf.cmd" prepare --source "$SRC" --pages 24-32 --project "$PROJ" --title '<书名>'

# 5) 构建 → 技术检查
& "$NF\nf.cmd" build --project "$PROJ"
& "$NF\nf.cmd" qa    --project "$PROJ"
```

到第 5 步为止只说明"环境和引擎通了"；**离交付还很远**——后面还有排版几何检查、字号回抽比对、逐页视觉审核、独立复编，见 `03-命令速查.md` 与 `04-踩坑与注意点.md`。
