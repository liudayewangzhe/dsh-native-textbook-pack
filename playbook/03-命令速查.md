## 1. 引擎 `nf.cmd`（book 主链）

| 子命令 | 参数（✓ = 必填） | 说明 |
|---|---|---|
| `doctor` | 无 | 输出 JSON；`ok=true` 才是 0 退出码 |
| `prepare` | ✓`--source` ✓`--pages` ✓`--project` ✓`--title` | 抽取只读来源 packet。`--pages` 是 **PDF 物理页码**，如 `24-32`、`1,13-65,69-89` |
| `asset` | ✓`--project` ✓`--page` ✓`--bbox X0 Y0 X1 Y1` ✓`--name` `--kind` `--figure-kind` | 从来源页登记图资产。`--bbox` 是**完整来源页的 PDF 点坐标**（4 个 float，空格分隔） |
| `redraw` | ✓`--project` ✓`--spec` ✓`--name` | 原生矢量重绘（转发到 `engine\redraw.py`） |
| `build` | ✓`--project` | XeLaTeX 构建 |
| `qa` | ✓`--project` | 技术检查，产出 `qa/*.json` |
| `release` | ✓`--project` | 发布门；有未决项/未覆盖/指纹过期时拒绝 |

**取值枚举**（来自源码常量，别写错）：

- `--kind`（`ASSET_CROP_KINDS`，默认 `vector_pdf`）：`vector_pdf` / `source_raster` / `source_pdf` / `page_raster`
- `--figure-kind`（默认 `mixed`）：`photograph` / `plot` / `schematic` / `mixed` / `qr_code`

```powershell
# 环境
& "$NF\nf.cmd" doctor

# 建项目（只读原稿；project.json 里的来源哈希与页码是事实边界）
& "$NF\nf.cmd" prepare --source "$SRC" --pages 24-32 --project "$PROJ" --title '计算物理：从原理到实践'

# 从来源页登记一张矢量图（bbox 是来源页 PDF 点坐标）
& "$NF\nf.cmd" asset --project "$PROJ" --page 29 --bbox 316.69 207.98 548.84 355.26 `
  --name f0029-1.1.2 --kind source_raster

# 原生矢量重绘（spec 是 JSON 图形规范）
& "$NF\nf.cmd" redraw --project "$PROJ" --spec "$PROJ\figures\f12.json" --name f12-native

# 构建 → 技术检查 → 发布
& "$NF\nf.cmd" build   --project "$PROJ"
& "$NF\nf.cmd" qa      --project "$PROJ"
& "$NF\nf.cmd" release --project "$PROJ"
```

**内存门槛**（§见 `02-环境与依赖.md` §6）：`NF_RAM_FLOOR_MIB` 可放宽到 512 MiB–1 GiB 之间，超出范围会被夹取。

```powershell
$env:NF_RAM_FLOOR_MIB = "700"   # 仅监工自己的重活命令上设；不要下发 worker
```

## 2. 三个排版检查脚本 + 视觉审核图（`$SK\scripts\`）

### 2.1 `check_typography.py` — 几何事实

| 参数 | 默认 | 说明 |
|---|---|---|
| ✓`--pdf` | — | 待查 PDF |
| `--mode` | `book` | `book` \| `slide`（不同预设） |
| `--out` | — | JSON 报告路径 |
| `--report` | — | Markdown 报告路径 |
| `--pages` | 全部 | 只查指定页，如 `1-20,35` |
| `--fail-on` | `never` | `error` \| `warn` \| `never` |
| `--max-pages` | `0` | 0 = 全部 |

给的是**几何事实**：越纸、文字互压、文字被填充盖住（按对比度）、按字号的行距节奏、版心留白、行末填充率。**它不证明页面好不好看**（`references/visual-audit.md` §6.2）。

```powershell
& $PY "$SK\scripts\check_typography.py" --pdf "$PROJ\build\main.pdf" --mode book `
  --out "$PROJ\qa\typo.json" --report "$PROJ\qa\typo.md" --fail-on error
```

### 2.2 `compare_typography.py` — 源 vs 交付的字号/行距回抽（**硬门禁**）

| 参数 | 默认 | 说明 |
|---|---|---|
| ✓`--source` | — | 源 PDF |
| ✓`--target` | — | 交付 PDF |
| `--mode` | `book` | `book` \| `slide` |
| `--pages` | 全部 | 两文件同范围，如 `2-15` |
| `--tol-pct` | 随模式 | 逐级容差（**±3%**；外文源→中文放宽到 **±10%**） |
| `--scale` | `auto` | `relayout` \| `cross-language` \| `auto` |
| `--global-tol` | 随模式 | 整体比例容差 |
| `--out` / `--report` | — | JSON / Markdown |

**最重要的一项输出是 `body_scale_ratio`（正文字号整体比例）**：≈`0.75` 就是典型的 72/96 整册误缩，≈`1.0` 说明整体尺度保持。

```powershell
& $PY "$SK\scripts\compare_typography.py" --source "$SRC" --target "$PROJ\build\main.pdf" `
  --mode book --out "$PROJ\qa\size-compare.json" --report "$PROJ\qa\size-compare.md"
```

### 2.3 `check_slide_spacing.py` — 读 TeX 源查节点行盒冲突（slide 专用）

| 参数 | 默认 | 说明 |
|---|---|---|
| ✓`--tex` | — | 主 TeX 源 |
| `--lead` | `13.3` | 正文行距 pt |
| `--body` | `9.5` | 正文字号 pt |
| `--min-gap-ratio` | `0.90` | 相邻项最小间距 = 前项行盒 × 该系数（**0.90**，不是 0.75） |
| `--max-x` | `20.0` | — |
| `--report` / `--out` | — | Markdown / JSON |

> ⚠️ 这个脚本的第一版判据取 `0.75`，等于"允许相邻项重叠 25% 行盒"，**放过了真实缺陷**；收紧到 `0.90` 后才抓到。这是"检查器必须做负向回归"的活案例（`references/slide-pitfalls.md` §D2、`sessions\09-native-textbook技能升级.md`）。

### 2.4 `check_slide_pdf.py` — slide 技术检查

| 参数 | 必填 | 说明 |
|---|---|---|
| `--pdf` | ✓ | 待查 PDF |
| `--config` | — | 检查配置 JSON |
| `--out` | ✓ | 结果 JSON |

它把 `visual_review` **固定写成 `not_performed`**，等 `visual-audit` 来填——不可以预填 `performed`。

配置示例（坐标单位 PDF pt，页码从 1 开始；来自 `references/slide-native-pdf.md`）：

```json
{
  "expected_pages": 3,
  "width_mm": 128,
  "height_mm": 96,
  "max_raster_images": 0,
  "require_embedded_fonts": true,
  "page_titles": {"2": "原生数学", "3": "原生矢量图"},
  "required_strings": {"2": ["均方根", {"text": "dt", "min_count": 2}]},
  "body_region_pt": [0, 38, 363, 264],
  "content_bounds_pt": [7, 38, 356, 260]
}
```

```powershell
& $PY "$SK\scripts\check_slide_pdf.py" --pdf "$PROJ\main.pdf" `
  --config "$PROJ\slide-check.json" --out "$PROJ\qa\slide-check.json"
```

### 2.5 `render_review_sheets.py` — 生成**看图用**的接触表与高倍页图

| 参数 | 默认 | 说明 |
|---|---|---|
| ✓`--pdf` | — | 交付 PDF |
| ✓`--out` | — | 输出目录 |
| `--sheet-pages` | `6` | 每张接触表放几页 |
| `--thumb-width` | `480` | 缩略图宽 px |
| `--hi-res-pages` | `""` | 高倍页，如 `"1,3,5-8"` |
| `--hi-res-zoom` | `3.0` | 高倍倍数（3 ≈ 216 dpi） |
| `--all-pages` | off | 渲染全部单页图 |
| `--cols` | `3` | 接触表列数 |
| `--label-pages` | `true` | 页标签 |
| `--poppler-dpi` | `0` | >0 时启用 Poppler 交叉渲染 |
| `--no-sheets` | off | 不生成接触表 |

```powershell
& $PY "$SK\scripts\render_review_sheets.py" --pdf "$PROJ\build\main.pdf" --out "$PROJ\qa\review" `
  --sheet-pages 6 --thumb-width 480 --hi-res-pages "1,3,5,6,8,10,11,13,15" --hi-res-zoom 3 --poppler-dpi 144
# 第二渲染器（可选）
pdftoppm -r 144 -png "$PROJ\build\main.pdf" "$PROJ\qa\review\poppler-144"
```

输出 `contact-01.png` 等接触表、高倍 PNG，以及 `manifest.json`（记录输入 PDF 的 sha256、页数、每页 PNG 的 sha256、缩放倍数与工具）。**审查证据绑定这些哈希。**

## 3. 引擎辅助脚本（`$NF\scripts\`）

| 脚本 | 参数 | 用途 |
|---|---|---|
| `preflight_pdf.py` | ✓`--manifest` ✓`--out` | 只读来源前检：记录哈希、逐页观测与候选；**不翻译、不 OCR、不访问外链** |
| `plan_document.py scaffold` | ✓`--preflight` ✓`--project` [`--retrospective`] | 把前检复制进项目 `planning/preflight.json` 并绑定 SHA-256；建立 `layout-plan.json`（新建计划**始终待定**，首次 `check` 应当失败） |
| `plan_document.py check` | ✓`--project` | 校验计划；缺项/过期/不合法 → **退出码 2**，通过 → 0。只读，不写"通过"状态 |
| `scaffold_inventory.py` | ✓`--project` | 生成 `source_inventory.json` 的空数组骨架（**不覆盖已有人工清单**）；objects 必须是数组 |
| `merge_chunks.py` | ✓`--project` ✓`--chunks <文件...>` | 按阅读顺序拼接 chunk；给内容 ID 加 chunk 前缀、保留原书编号、合并期望与未决项 |

```powershell
# 前检清单：inputs.json 形如 [{"id":"source-a","path":"<原稿绝对路径>"}]
& $PY "$NF\scripts\preflight_pdf.py" --manifest "$NF\reports\inputs.json" --out "$NF\reports\source-preflight"
# 版式计划
& $PY "$NF\scripts\plan_document.py" scaffold --preflight "$NF\reports\source-preflight\book-a.json" --project "$PROJ"
& $PY "$NF\scripts\plan_document.py" check --project "$PROJ"
# 扫描件清单骨架
& $PY "$NF\scripts\scaffold_inventory.py" --project "$PROJ"
# 按顺序合并（显式列出文件，顺序即阅读顺序）
& $PY "$NF\scripts\merge_chunks.py" --project "$PROJ" `
  --chunks "$PROJ\chunks\0000.json" "$PROJ\chunks\0002.json" "$PROJ\chunks\0001.json"
```

> `merge_chunks.py` 的 `--chunks` 是 `nargs='+'`，**文件顺序就是阅读顺序**；项目里通常另存一份 `chunk_order.json` 记录顺序与页区间（`sessions\01-起始-学习native-textbook并为ME4300搭流水线.md`）。

## 4. 扫描件修复流水线（`$SK\scripts\scan_repair\`）

**顺序不可换**：数据形状类修复必须在 `merge` 之前，因为 `merge` 会把分片物化成 `source_inventory.json` 与 `content.json`（`references/scanned-source-repair.md` §1）。

### 4.1 标准序列

```powershell
$S   = "$SK\scripts\scan_repair"

# --- A. 数据形状修复（幂等，可反复跑）---
& $PY "$S\fix_bad_json.py"           # 分片 JSON 非法转义（notes 里的单反斜杠）
& $PY "$S\fix_object_kind.py"        # 证据对象的 kind 越界
& $PY "$S\fix_figure_tex.py"         # 自写 \includegraphics
& $PY "$S\fix_literal_blocks.py"     # code/console 块的多余字段
& $PY "$S\fix_empty_text.py"         # text 为空的证据对象
& $PY "$S\fix_excluded_fields.py"    # excluded 条目缺 id/page/kind/text
& $PY "$S\fix_glyphs.py"             # 字体没有字形的字符
& $PY "$S\fix_cdots.py"              # 文本模式里的 \cdots
& $PY "$S\clamp_bbox.py"             # bbox 越界/退化
& $PY "$S\fix_array_cols.py"         # 矩阵/表格声明列数不足
& $PY "$S\auto_continues.py"         # 跨页标记只标单侧

# --- B. 引擎流程（prepare 必须在 merge 之前）---
$pages = & $PY "$S\gen_pages.py"     # 已转写页的紧凑范围串，如 "1,13-65,69-89"
& "$NF\nf.cmd" prepare --source "$SRC" --pages $pages --project "$PROJ" --title '<书名>'
& $PY "$S\merge_workers.py" --pages $pages      # 第 1 次：分片 → content.json
& $PY "$S\make_assets.py"   --pages $pages      # 裁图并改写 figure 块
& $PY "$S\merge_workers.py" --pages $pages      # 第 2 次：把 asset 纳进来
& "$NF\nf.cmd" build --project "$PROJ"

# --- C. 门禁（每批必跑）---
& $PY "$S\audit_coverage.py" --pages $pages     # 墨迹行覆盖
& $PY "$S\check_numbering.py"                   # 公式/图/表编号连续性
& "$NF\nf.cmd" qa --project "$PROJ"
```

**两次 `merge` 是必需的**：`make_assets` 读的是上一次 merge 产出的 `work/figure_requests.json`，新页的插图当轮还没进那个文件。

### 4.2 参数表（只列有 argparse 的脚本）

| 脚本 | 参数 | 默认 | 用途 |
|---|---|---|---|
| `audit_coverage.py` | `--pages` / `--dpi` / `--min-ink` / `--report` | `""` / `90` / `6` / `""` | **墨迹行覆盖审计**：源页渲染成像素，逐行取墨迹，检查每条文字行是否落在某对象 bbox 内 |
| `check_numbering.py` | **无参数** | — | **编号连续性**：按章统计公式/图/表编号，报缺口 |
| `detect_partial_pages.py` | `--pages` / `--threshold` | `""` / `0.12` | **半页漏读检测**：比较 objects 的 y 上界与页面实际墨迹上界 |
| `run_pipeline.py` | `--skip-build` / `--audit` | off / off | 串起修复→prepare→merge→出图→merge→build |
| `run_build_loop.py` | `--rounds` | `4` | 闭环重试：修复→准备→合并→出图→合并→编译，遇 unresolved 自动重来 |
| `merge_workers.py` | `--pages` / `--allow-pending` | `""` / off | 分片 → `content.json` / `source_inventory.json` |

> `audit_coverage.py` 与 `check_numbering.py` 是**唯二能抓"少了半页"的机械门禁**——排版类检查抓不到。两者都只证明"没有未覆盖的行/没有编号缺口"，**不证明文字转写正确**。

| 图形/资产 | `fix_figure_tex.py` `fix_figure_fields.py` `fix_figure_number2.py` `fix_bare_figure_blocks.py` `fix_caption_only_figures.py` `fix_fig_trim.py` `fix_asset_names.py` `fix_asset_hashes.py` `make_assets.py` |

## 5. slide 链的检查组合（不走 `nf.cmd release`）

```powershell
# 1) 技术检查
& $PY "$SK\scripts\check_slide_pdf.py" --pdf "$PROJ\main.pdf" --config "$PROJ\slide-check.json" `
  --out "$PROJ\qa\slide-check.json"
# 2) 排版几何
& $PY "$SK\scripts\check_typography.py" --pdf "$PROJ\main.pdf" --mode slide `
  --out "$PROJ\qa\typo.json" --report "$PROJ\qa\typo.md"
# 3) 折行/间距/空节点
& $PY "$SK\scripts\check_slide_spacing.py" --tex "$PROJ\main.tex" --report "$PROJ\qa\spacing.md"
# 4) 字号回抽（门禁）
& $PY "$SK\scripts\compare_typography.py" --source "$SRC" --target "$PROJ\main.pdf" --mode slide `
  --out "$PROJ\qa\size-compare.json" --report "$PROJ\qa\size-compare.md"
# 5) 视觉审核图
& $PY "$SK\scripts\render_review_sheets.py" --pdf "$PROJ\main.pdf" --out "$PROJ\qa\review" `
  --hi-res-pages "<本次高风险页>" --hi-res-zoom 3 --poppler-dpi 144
```

**slide 发布是独立清单，不是 `nf.cmd release`，不得写 `nf released`**（`SKILL.md` §slide 执行 §8）。
