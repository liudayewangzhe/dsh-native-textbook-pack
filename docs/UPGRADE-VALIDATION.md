## 真实课件模板验证

保留的 `assets/slide-template.tex` 在 Windows、TeX Live 2024 / XeLaTeX 下真实编译三遍，输出 3 页、128×96 mm。原始版本末行分式的 `dt` 超过约定正文下界约 1.34 pt；用同一配置复现失败后，将该行上移 2 mm。图的宽高改为有明确端点的原生尺寸线。

修复后：

- `check_slide_pdf.py`：3 页、0 issues、字体嵌入、运行时位图为 0。仅在实际查看矩阵括号后，逐字符允许 Computer Modern 的四个分段括号 PUA，并记录原因。
- `check_typography.py`：0 error、2 warn。两项告警分别是有意设计的色带底色，以及页脚 4.8 pt 被全页字号众数规则计入正文候选；实际查看确认可读，未删告警冒充无问题。
- L1 查看全部 3 页；L2 实际查看原生数学、矩阵、积分上下限、分母、图形轴/尺寸线及标签；生成 PyMuPDF 3× 与 Poppler 144 dpi 全 3 页材料并交叉查看。
- 源码间距工具不展开模板的 `T/B` 宏，扫描为 0 节点。新版本明确报 `not_applicable`，没有将它记作自动检查通过；对应文本行盒由最终 PDF 几何与本次全页视觉检查核验。
- 将 TeX 复制到另一目录，以相同引擎独立编译三遍；3 页逐像素相等、书签相等、TeX 字节相等。PDF 文件哈希因生成元数据不同而不同，未把文件字节相等作为像素复编的前提。

该合成模板最终 PDF SHA-256：`57bf177a0a93774b3e9257c6b5136cf4fc5bdff434e4fc0009d1411fd1ee533c`。这是本机当次构建指纹，不是不同字体/TeX 环境都应产生相同文件哈希的承诺。没有把该三页检查外推为历史全部教材的视觉或语义验收。

## 规则一致性与独立前向检查

独立审查实际演练了“一个包失败 → 术语新增别名 → 模板改变 → 局部修订与恢复”：相关包重译，未变译文仅重建；旧 brief 被拒绝，最终只到 `draft_verified` 且 `review_valid:false`。另演练 4:3 课件加授权新封面，保留页几何与独立 slide 发布。

本次统一了封面模式、项目字号目标与跨语诊断阈值、L1/L2 覆盖、三遍独立复编、扫描 inbox / direct_inventory 权威，以及绘图工具建议的适用范围。状态工具不自动判断术语反馈真伪或合并歧义；这些仍由监工回源裁决。

引擎还修复了真实可复现的内存规则冲突：旧实现会接受 `NF_RAM_FLOOR_MIB=700` 并放行模拟 800 MiB；新实现对低环境值及低显式参数都保持 1 GiB 底线，允许提高门槛，并有正负回归。没有修改历史项目的 PDF、源码或审查记录。
