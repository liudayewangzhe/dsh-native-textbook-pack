# 课件排雷清单（症状 → 根因 → 判定 → 检查）

**为什么会有这份文件**：本技能在同一个 15 页课件上被用户连续指出三轮同类排版缺陷。前两轮我把问题当"待修 bug"逐个修掉，**没有把它沉淀成规则**，所以第二轮、第三轮又犯了同一类错误。

这份文件的目的就是**终止这种循环**：每一条都写成"用户会怎么描述 → 真正的原因 → 怎么判定 → 用什么检查"。

## 使用方式（强制）

1. **动手排任何一页之前**：先读本文件，特别是指南 §A（坐标与几何）。
2. **每页做完、进入审核之前**：拿本文件 §C 的"逐页自查表"过一遍，**不许只凭印象说"看过了"**。
3. **每次交付后**：把本轮新出现的缺陷**回写**到本文件（见 §D 的沉淀流程）。回写是交付的一部分，不是可选项。

本文件按"缺陷类别"组织，不按页码或项目组织——项目事实会过期，类别不会。

## §A 坐标与几何（**最高频、最致命**）

### A1 坐标系方向：必须用实验确定，禁止靠直觉

| 项 | 内容 |
|---|---|
| 用户会怎么说 | "标签飘着""位置不对""本应在上面却跑到下面" |
| 真正原因 | 手写坐标系的 **y 方向判断反了**。若模板用 `y=-1mm` + 左上原点，则 **y 增大 = 页面向下**（y 就是"离纸顶多少毫米"），与 PDF 的 pt 坐标系方向相反 |
| 判定 | 画出 `y=10 / y=50 / y=90` 三条线，渲染后确认哪条在页顶。**先做这个 3 行实验，再动手排版** |
| 检查 | 实验本身；`check_typography.py` 只看渲染结果，发现不了"方向搞反" |
| 记法 | `y` = 从纸顶往下的毫米数。想放"页面上方"就用**小** y |

**这条单独占一节**，因为它在实测中连续造成 3 轮返工（正弦图的 `a`、`2π/ω` 位置反复错，根因只有一个）。

### A2 标签与线的净空必须含"公式行盒"，不能只算基线

| 项 | 内容 |
|---|---|
| 用户会怎么说 | "左上角有点擦线" |
| 真正原因 | 标签是数学（`$u(t)=a$`）时，**括号、下标、分式的下伸部分**会超过字形基线约 1–2mm；按基线算间距就会擦到相邻的线 |
| 判定 | 标签与任何线之间留 **≥1.5mm** 净空；含括号/分式/下标的标签按 **2mm** 留 |
| 检查 | 放大 5–7 倍看图；`check_typography.py` 的 `text_overlap` 只在重叠面积够大时才报，擦线容易漏 |

### A3 参考轴线不得穿过标注字形

| 项 | 内容 |
|---|---|
| 用户会怎么说 | "坐标轴都穿数字 0 而过" |
| 真正原因 | 标注用**居中**锚点放在轴上，轴就从字形中间穿过 |
| 判定 | 轴上的数字一律**锚在轴的一侧**：纵轴上的 `0` 用 `anchor=west` 放轴右侧，`t=0` 用 `anchor=east` 放轴左侧 |
| 检查 | 放大看图；`check_typography.py` 的 `text_obscured_by_fill` 覆盖不到"线穿字" |

### A4 度量线的两端必须落在参考轴上，否则读不出长度

| 项 | 内容 |
|---|---|
| 用户会怎么说 | "竖向虚线没有往下延伸到横轴，导致竖向长度不明确" |
| 真正原因 | 标注"宽度/高度"的虚线只画在图形附近，没落到作为**基准的轴线**上，读者无法读出量值 |
| 判定 | 任何表示宽/高的虚线或双箭头，**两端都要落到基准轴**（横轴或纵轴）或其延长线上；水平收口线画在图形与文字之间 |
| 检查 | 放大看图，自问"这个数字能不能对着一条轴直接读出来？" |

## §B 文本与间距

### B1 长句折行后，间距要按**实际行数**留

| 项 | 内容 |
|---|---|
| 用户会怎么说 | "这条文字和上一条叠在一起了" |
| 真正原因 | 手写坐标里，文本的垂直占位 = **行数 × 行距**，而人不会每次去数行数 |
| 判定 | 单行间距 ≥1.0 行距；**两行项之后**的间距 ≥2.2 行距。不要凭感觉写 8.5mm 就当够了 |
| 检查 | `check_slide_spacing.py`（**为这条专门写的**，见 §D） |

### B2 两式合排会超宽

| 项 | 内容 |
|---|---|
| 用户会怎么说 | "右边被切掉了" |
| 真正原因 | 两个等式用 `\qquad` 连排，实际宽度可能是可用宽度的 1.4 倍 |
| 判定 | 先估算：中文按字号全宽、西文按半宽累加；超过 `text width` 就改**公式内换行**（`gathered`） |
| 检查 | `check_slide_spacing.py` 会报"节点超宽"；放大看图看右端 |

### B3 残留的空节点

| 项 | 内容 |
|---|---|
| 用户会怎么说 | （通常看不见，但会挤压布局） |
| 真正原因 | 编辑过程中留下的 `\node[...] at (...) {};` |
| 判定 | 空节点一律删；它会占位并可能与别的节点同坐标 |
| 检查 | `check_slide_spacing.py` 的 `empty_text_node` |

## §C 图形与标注

### C1 标注"飘着"：必须与所指对象建立可见联系

| 项 | 内容 |
|---|---|
| 用户会怎么说 | "这个 a 跟 2π/ω 还有箭头就空中飘着干嘛呢" |
| 真正原因 | 标注只放在"看起来空的地方"，**没有引线、也不在所指对象的邻近位置**，读者无法知道它标的是什么 |
| 判定 | 每条标注三选一：① 引线连到所指对象（并对准该对象的特征点，如**波峰**而非波谷）；② 紧邻对象；③ 跨距标注的两端落在被跨的两个特征点上 |
| 检查 | 放大看图，逐条自问"这个标注指着什么？" |

### C2 图形里的竖虚线要落到横轴

同 §A4。

### C3 "无重叠"不等于"语义正确"

| 项 | 内容 |
|---|---|
| 真正原因 | 端点、方向、交集、单位、图文对应是**语义属性**，矢量和清晰只是表示属性 |
| 判定 | 逐条比对节点/边/方向/标签归属；箭头两端用命名锚点，不用裸坐标 |
| 检查 | 看图 + 语义合同逐条核对（见 [figure-craft.md](figure-craft.md)） |

## §D 工程与流程

### D1 母版宏的调用顺序会影响 TikZ overlay 的页面原点

| 项 | 内容 |
|---|---|
| 用户会怎么说 | "整页内容不见了/只有页脚" |
| 真正原因 | `\pdfbookmark` 放在 `\begin{tikzpicture}[remember picture,overlay]` **之前**，其内部状态破坏 overlay 页面原点；编译退出码仍为 0、日志四桶全空 |
| 判定 | bookmark 放在绘图**之后**，并给整页加 `\begingroup...\endgroup` 防宏泄漏 |
| 检查 | 交付 PDF 抽取文字 bbox 是否落在页内（`check_slide_pdf.py` 的 `text_outside_page`）；**必看渲染图** |

### D2 检测器本身的误报/漏报要一并修，且必须有负向回归

| 项 | 内容 |
|---|---|
| 触发情形 | ① 中文书校对报"文字重叠"，实际是数学逐字形 span；② 比对工具把页脚 4.8pt 当成正文；③ 间距判据系数 0.75 等于"允许重叠 25% 行盒"，放过了真实缺陷 |
| 判定 | 检查器要能被**已知有缺陷的输入**触发；一个只会在好稿上通过、在坏稿上也通过的检查器等于没有 |
| 检查 | 每次新增/修改检查器，必须跑一次**负向回归**：把修复前的输入喂进去，确认它报错，并记录退出码 |

### D3 审核顺序：先机械检查缩范围，再逐页看图，最后逐条对清单

先用 `check_typography.py` / `check_slide_spacing.py` / `check_slide_pdf.py` 把可疑页缩到少数；再对**全部**输出页做 L1 接触表目检；再对高风险页做 L2 高倍；**最后拿 §A–§C 逐条对照**。

**"我逐页看过了"不是证据。** 本轮实测：我看过全部 15 页，仍漏掉 4 处（长句折行重叠、空节点、标签擦线、度量线未落轴）。

## §D 沉淀流程（每次交付后必做，不能省）

1. **记录**：本轮新出现的缺陷，按 §A–§D 的类别归位；写清"用户的原话 → 根因 → 判定 → 检查"。
2. **能自动化的立刻自动化**：若某类缺陷可以用脚本判定，就写进 `scripts/`（如本轮的 `check_slide_spacing.py` 就是为 B1 写的）。
3. **不能自动化的写成清单条目**：进入 §A–§C，供下次逐条对照。
4. **回写到对应参考文件**：规则的主体放在 [chinese-typography.md](chinese-typography.md)、[figure-craft.md](figure-craft.md)、[cover-and-geometry.md](cover-and-geometry.md)；本文件只保留"症状索引 + 判定阈值 + 检查工具"。
5. **修完后自问**：这条规则能不能在下一次**开工前**就阻止我犯？如果不能，它写得还不够具体。

> **判断一个"升级"是否真的有用**：把规则交给一个没读过它的自己，
> 他能不能**在不看图的情况下**避免这个缺陷？能，才算写成可执行条款。
