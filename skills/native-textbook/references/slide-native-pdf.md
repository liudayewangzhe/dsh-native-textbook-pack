# 保留 PPT 风味的原生中文 PDF

用于用户希望中文输出保留课件页级结构、横版比例、标题带、项目符号、图文分组和适当留白的任务。若用户要把课件扩展为连续教材，返回book；若交付物含可编辑PPTX，使用presentations处理该交付物。只有PDF来源时，不能声称恢复动画、演讲备注或被覆盖的原始文本。

## 来源合同先于版式

读取完整授权源页并渲染查看。记录来源SHA256、物理页数、MediaBox/CropBox与旋转、实际可见标题、文本阅读顺序、每个公式/推导项、每幅图的全部标签、定义框与列表归属。文字层有标题而渲染不可见时，分开登记；不能凭抽取顺序恢复叠放关系。

默认一源页对应一输出页，保留源页序。只有用户明确授权改变页数时，才在页对应合同登记拆页、合页或新增封面及其来源范围；中文扩展先尝试语义拆行和对象重排，不能自行改成书籍流水。当前状态工具只支持 `source_pages` 与 `output_pages` 的一一映射（可改变页码）；若授权拆页/合页，使用另行明确的页对应合同，由主控集成与验收，不伪造该工具已经支持多对多。新增解释、编辑性标题、来源笔误修正单独记录，不伪装原文。

按页建立三种对象合同：

- 内容：原文/中文/LaTeX、源区域或ID、数学条件、编号、段内强调、保留或明确排除理由。
- 几何：源页尺寸与单位、目标页尺寸、阅读区、标题区、页脚区；对象左上/中心/基线是哪一种锚点，宽高与预期行数。保留一份可核对的页布局数据。
- 图形：每个轴、端点、箭头方向、曲线关系、标签和图注；来源裁切或重绘方法。示意波形可用其解析定义重绘，未知测量数据不能重新采样。

例如冲激近似的宽度和高度共同决定积分。只画一条看似正确的曲线，却漏掉ε、2ε、1/ε或基线，不算完整图。展开推导最后一项即使最终为0，也不能为缩短行长而删除。

## 选择输出链

目标仅为原生PDF时，优先让XeLaTeX直接排中文、数学、表格与TikZ/PGFPlots，保留源PDF内可验证的矢量图。可从 [最小课件模板](../assets/slide-template.tex) 开始；它提供页框、T文本、E显示数学和B项目符号。示例4:3尺寸、字体、颜色、字号均是可运行起点，必须按实际来源与使用场景调整，并重新验证样张。

避免不必要的“数学LaTeX→SVG→逐字形重建PPT→另一渲染器PDF”链。要保留SVG时保留经过验证的完整矢量对象，不能把其中text/path拆成普通文本框后假设变换仍等价。需要PPTX时另行测试presentation引擎对公式的支持，不能把PDF成功归为PPTX可编辑公式成功。

每一层只改变一次坐标体系：源PDF左上点坐标→指定裁区→资产自身原点→目标页坐标。注明pt/mm以及缩放、翻转、裁切原点；不混用整页y值和裁出图的局部y值。`text-anchor`、baseline/dy、嵌套transform和viewBox都属于几何语义，不能忽略。裁出资产逐个查看，确认底部轴、上下限、负号、图注及边缘标签；图片资源为空不证明没有裁切。

来源bbox的左边界、上边界不等于目标公式中心或文本基线。工作包要给完整bbox和明确的源/目标锚点，母版与内容worker分工也要显式锁定；模板已有标题/顶带/页脚时，worker不得再次绘制这些节点。合并时核对题干动作、强调范围和全部未决项，不以可编译为由接受推测布局。

PDF坐标与字体大小是72 pt/in：`mm=pt×25.4/72`。PPTX使用36000 EMU/mm；CSS px/raster dpi属于显示层，不能把PDF抽取字号乘72/96。遇到整页约同倍放大/裁切，先用无文字、无公式的四边标记矩形校准反馈工具，再对比导出的真实PDF。Signals实测harness的LibreOfficeKit presentation tile预览约放大1.5倍，而convert PDF独立渲染正常；Windows 144 DPI与其相符，但尚未做改变系统DPI的因果实验。不要靠整体缩字/移位迁就未校准的预览器。

当前可用绕过办法是`PPTX convert → 实际PDF → render PDF`；同harness CLI读取PDF走PDFium分支，96 dpi样张已验证比例正常。记录输入PDF哈希和`backend=pdfium`，不能把PPTX直接预览的结果充当PDF验证；Poppler/PyMuPDF也可作为独立渲染。这个绕过不修复文档中已有的错误公式和crop，也不等于harness原生presentation tile已经修好。

图的SVG/PDF容器不证明内部是矢量。检查实际可见image occurrences和资产职责；资源字典里的共享图片数也不等于每页实际显示次数。Signals原稿的正弦曲线即为嵌入PNG，旧稿误称全部波形矢量。示意解析波形可以原生重绘；真实图片按来源与项目政策登记。

## 页级排版

标题、正文、公式、图和页脚按层次放置。短列表保留课件节奏；稀疏页保留合理留白。中文内容尽量直接，不为了补满页面重复添加英文括注。正文和公式有统一字号/行距；每个公式按真实行盒考虑积分限、根号、矩阵和分数的高度。

**页级几何写成毫米合同**（实测可复用的 4:3 中文课件，128×96 mm）：顶带 y 0–3.13、标题带 y 3.13–13.03（空标题不画带）、正文区 x 3.4–124.5 / y 18–88、页脚保留 y 93.3–96。任何正文/公式/图的**外框**（含积分上下限、根号、矩阵、分数）必须落在正文区内，不得伸入页脚保留区。完整表与封面构成见 [cover-and-geometry.md](cover-and-geometry.md)。

**字号与行距按 [chinese-typography.md](chinese-typography.md) 的模数确定**，不要逐页试。中文标点、中西文间距、缩进与分页控制同见该页。关键：**声明值 ≠ 实测值**——模板写的字号与最终 PDF 抽取的字号会差（实测封面 16→14.94 pt，正文 9.5→中文 9.46 / 数学 9.96，行距 13.3→15.6–15.9），必须回抽实测并与项目合同目标比对，偏差 >±3% 先查因。源字号用于忠实复刻的目标与跨语诊断；工具 auto 模式的 ±10% 告警阈值不自动豁免合同偏差。

长公式先按等号、加项或语义分成aligned续行。不要缩窄整式到难以辨认；不能删项解决宽度。标题为空时，不自动画一条空灰标题带，除非来源确实有该带。页脚是保留区域，不把证明末句或公式伸进去。

模板直接在TikZ `node`内设置字体并排数学。不要在TikZ绘图层内部用未显式设置完整字体上下文的`\sbox`测量数学；PGF的绘图上下文可能处于nullfont，结果即使编译退出为0，字形仍会消失。出现`Missing character ... nullfont`立即修复，在真实字体节点或绘图外测量，再重新看图；不能只调整框尺寸。

## 风险样张与回归

先制作本次原稿真实风险对象所在的完整页：高矩阵、多层分数/根式、积分上下限、长推导、多面板图、图注和定义框、最密习题页等。选择由实际风险决定，不固定首页/中页/尾页或样张数量。样张使用将来量产的相同字体、宏和输出链。变更这些条件后，重新验受影响对象。

常见失败及定位：

| 最终PDF症状 | 先查机制 | 修复后核验 |
|---|---|---|
| 图只剩顶端、轴/图注消失 | 源bbox是否真实；单位；裁切与重基原点；图注是否在viewBox外 | 每个资产与整页同时看，所有标签完整 |
| 矩阵顺序倒置、上下限反转 | y方向、SVG嵌套transform、基线/dy、解析器重排 | 按源逐字逐符号看最终数学 |
| 分母或根号消失 | 输出链是否丢路径/字形；nullfont；裁区高度 | dt、m、R等分母、分数线与根式全部在PDF中可见 |
| 数学出现多余逗号 | LaTeX微小空白`\,`是否被中间解析当作字符 | 最终公式和源码同时核对 |
| 内容正确而等式少一项 | worker/布局数据遗漏或缩行时删项 | 核对展开项与积分区间，不能只验证最终值 |
| 检查说通过而PDF仍坏 | 检查的是PPTX/XML/源码/旧preview还是当前PDF | 绑定最终PDF哈希；实际使用同一个最终渲染器 |
| 页尾与页脚相撞 | 字符长度代替行盒高度；公式基线未计上下限 | 独立页底图、正文末句、页脚均完整 |

这些机制来自Signals课件的源/差稿、源码和渲染核验；对应项目诊断在交付包`reports/harness-root-cause.md`，不依赖该历史文件才能执行本流程。个案题目、页码和术语不升级为全局规则。

## 技术检查和发布

构建直接运行XeLaTeX，保存命令、退出码、完整日志及实际PDF哈希。检查缺字、nullfont、溢出、未解析引用与实际页数。无需把独立课件伪装为Native Forge的book项目。

先跑排版几何检查（越纸、文字重叠、不可见文字、行距节奏、版心留白）：

```powershell
python scripts/check_typography.py --pdf "项目\main.pdf" --mode slide --out "项目\qa\typo.json" --report "项目\qa\typo.md"
```

用带PyMuPDF的Python运行：

```powershell
python scripts/check_slide_pdf.py --pdf "项目\main.pdf" --config "项目\slide-check.json" --out "项目\qa\slide-check.json"
```

配置示例（坐标单位为PDF pt，页码从1开始；下列正文框对应本页 128×96 mm 样张的 x 3.4–124.5 / y 18–88 mm，其他母版须重新换算）：

```json
{
  "expected_pages": 3,
  "width_mm": 128,
  "height_mm": 96,
  "max_raster_images": 0,
  "require_embedded_fonts": true,
  "page_titles": {"2": "原生数学", "3": "原生矢量图"},
  "required_strings": {"2": ["均方根", {"text": "dt", "min_count": 2}]},
  "body_region_pt": [9.64, 51.02, 352.91, 249.45],
  "content_bounds_pt": [9.64, 51.02, 352.91, 249.45]
}
```

维度/页数、图片数量、字体嵌入、字符和bbox是技术信号。按项目的照片政策设置图片阈值，不能要求含照片的所有课件都为0。`required_strings`只检查抽取文字是否有指定片段，不能证明公式顺序、条件、图标签或语义正确；bbox不能识别所有遮挡/视觉重叠。标题若未指定区域，只检查该页文本；需位置检查时设置`title_region_pt`或逐页`title_regions_pt`。记录检查器明确的限制。

私用字符默认报告异常，不等同于实际缺字。Computer Modern的分段矩阵括号可能抽取成F8EE/F8F0/F8F9/F8FB；确认字体与实际可见括号后，可在项目配置`allowed_private_characters`里逐字符允许并记录`allowed_private_reason`。不要全局允许所有PUA或豁免U+FFFD。离纸检查使用无限抽取区域，避免先按纸张剪掉的字形逃过bbox检查。

最终验收另有来源对照和全部输出页实际目检：正文、每个数学项、图内标签、阅读顺序、对齐、留白与清晰度。目检按 [visual-audit.md](visual-audit.md) 执行：监工看全部输出页 L1；含公式、图、矩阵、表格、边注或封面的页逐页做 L2，**同时使用 PyMuPDF `Matrix(3,3)` 与 Poppler 144 dpi**，不能用其中一个代替另一个。独立审查者再复核高风险子集。逐对象核对，产物与记录绑定当前 PDF 哈希：

```powershell
python scripts/render_review_sheets.py --pdf "项目\main.pdf" --out "项目\qa\review" `
  --hi-res-pages "<全部需 L2 的页>" --hi-res-zoom 3 --poppler-dpi 144
```

审查记录绑定当前PDF和TeX/资产哈希，列出源页/输出页、方法、reviewer、issues、unresolved、**以及未覆盖的 limits**。不要让worker预填通过；没有实际看图就只能报 `visual_review: not_performed`。

独立发布包包含PDF、可编译TeX/矢量资产、构建说明、来源与内容合同、技术报告、页级审查和哈希清单。解包到另一目录，用相同引擎编译三遍；核对新 PDF 与交付 PDF 的页数、尺寸、逐页渲染 `.samples` 字节及书签 `get_toc()`，并核对源码/资产哈希。文本比较可辅助，不能替代像素和书签检查。只有当前技术检查、真实内容与视觉审查和未决项都完成后才交付。独立slide发布不是`nf.cmd release`，不得写`nf released`。

## 源码间距检查的适用范围

`check_slide_spacing.py` 当前识别 `\Slide[页码]` 与 `nftxt/nftxts/nfhd` 显式坐标节点；不展开任意 TeX 宏。扫描 0 节点时返回 `check_status:not_applicable`、退出码 2，不能当作间距通过。仓库的 `\T/\B` 模板属于这一限制：由主控实测最终 PDF 的文本行盒并逐页看图，或另行提供经验证的显式节点表示；记录替代核验的范围和证据。退出码 1 表示检出冲突，2 也可能是配置错误，必须读诊断区分，不能统一忽略非零。
