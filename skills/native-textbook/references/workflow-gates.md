# 放行门禁、证明边界与资源约束

本页回答两个问题：**每个检查能证明什么、不能证明什么**，以及**什么条件下才算交付**。

历史失败的总模式是：**把中间环节的成功当成最终产品的成功**——来源 ID 全覆盖当成没漏译、原生矢量当成图意正确、TeX 正确当成公式完整、编译完成当成版式合格。

## 1. 证明 / 不证明 矩阵

每个检查都有确定的证明边界。**越界引用它就是造假。**

| 环节 | 能证明 | **不能**证明 |
|---|---|---|
| 来源 ID 全覆盖 | 每个来源对象都被分配了去处 | 内容没漏译、没误绑定。一个块可以挂着整段 ID 却漏其中一句 |
| 工作包状态 `draft_verified` | 清单顺序、来源/上下文/术语依赖、输出哈希与草稿结构当前一致 | 译文/数学正确、无句子遗漏、图形正确、PDF已重建或审查；`review_valid` 始终为 false |
| 文字可提取 | 有文本层，可复制、可搜索 | 数学语义正确、翻译正确、阅读顺序正确 |
| `get_images()` 为空 | 页面资源字典里没有位图对象 | 页面是矢量；shading 可能被渲染器报成运行时图像 |
| PDF/SVG 后缀 | 容器格式 | 内部是矢量。把 PNG 包进 SVG 不转成矢量 |
| TeX 源码正确 | 源码逻辑与命令闭合 | 最终 PDF 的公式完整。分母可在渲染时被裁掉 |
| 编译成功 / 退出码 0 | 没有致命错误 | 内容正确、版式正确。未转义的 `%` 能让半页正文静默消失而编译成功 |
| 字体全部嵌入 | 字体字节在 PDF 内 | 字形可见、字形正确。`nullfont` 会让字形消失而退出码为 0 |
| 结构自检通过（包能打开、资源路径存在、文本框不越画布） | 包结构完整 | 分母没被裁、曲线没被裁、公式没变号 |
| 技术检查通过（`technical_pass=true`） | 页数/尺寸/越界/栅格数/字体嵌入符合配置 | 数学正确、视觉正确。**仍禁止交付** |
| 排版几何检查（本技能 `check_typography.py`） | 越纸对象、文字互相重叠、文字与填充重叠、按字号的行距分布、版心留白、行末填充率 | 页面好不好看、挤不挤、空不空；也不证明数学与翻译正确 |
| 接触表/高倍渲染图 | 该页**实际渲染出来**的样子 | 必须由人**真的看了**并对每个对象下结论 |
| 视觉审查（`visual-audit.md`） | 看过的页与对象、发现的问题、未覆盖的范围 | 只要 `limits` 没写全，审查就不完整 |
| 独立包复编 | 资源不依赖原工作目录 | 内容与版式正确 |
| 旧版本的审查 | 旧版本当时的结论 | 新版本。**新 hash 使旧复核全部失效** |

使用要求：

- 每份报告写清"本检查实际覆盖范围"和"未覆盖范围"。
- 状态字段**承载事实，不迎合门禁**。为通过 gate 清空 `unresolved` 或把观察转入 `observations_not_blocking`，是错误做法。
- 检查器的失效要有**负向回归**证据（见 §3）。

## 2. 放行五阶段与就绪条件

| 阶段 | 进入条件 | 该阶段证明 |
|---|---|---|
| 1. 规划可进入试排 | 授权范围与现有证据齐备；可列待补信息 | 方案、来源证据、待补项明确 |
| 2. 同类风险样张通过 | 该小节的可核验来源、对象 ID、候选版式、确切输出路径齐备 | 相同配置、字体、引擎、几何下的真实样张通过；**才放行批量** |
| 3. 草稿已生成 | — | 指定范围完整；**仍可有未决项，不称为成品** |
| 4. 技术检查通过 | 构建、来源覆盖、原生对象、几何、链接检查通过 | 技术层面通过；**不等于视觉与语义通过** |
| 5. 复核完成 → 已交付 | 授权源页与**全部**输出页完成实际对照；审查绑定当前指纹；独立审查高风险子集完成 | 内容、原生表示、编译、资源、纸面几何、实际渲染、链接、独立复编分别通过 |

**阶段就绪条件必须分层，避免循环门槛**：不能要求"规划任务先交一份已通过样张"。规划只需授权范围和现有证据；试排需该小节来源与输出路径；批量才要求同类样张已通过。

交付前的硬否决条件（任一存在即不得交付）：

- 存在 `unresolved` 未处理
- 有未覆盖的来源页
- 图形类型错误（该矢量却是位图、该原生却是截图）
- 编译失败或原生对象检查失败
- 有页未做视觉复核
- 审查指纹过期（PDF 已变但用旧审查）
- **检查器与渲染器不一致而未隔离原因**（先确认反馈工具是否可靠）

并保持四态严格区分：**`compiled` / `technical_pass` / `reviewed` / `released`**。

## 3. 检查器必须做负向回归

一个"永远通过"的检查器等于没有检查。**任何新增或修改的检查器，必须用已知有缺陷的产物证明它会失败。**

要求：

- 准备一份**已知有缺陷**的旧产物，检查器必须报出预期失败项，并记录**实际退出码**。
- 准备一份**配置错误**的输入（越界页码、负页数、不存在的必需字符、错误 bbox），检查器必须以"配置错误"退出，而不是静默通过。
- 同一个有缺陷的产物，在"给了项目内容合同"和"只给基础配置"两种情况下分别跑。历史实测：旧差稿在项目合同下报 5 项失败，在基础检查下 **0 issues 通过**——**说明"通过"的含义完全取决于配置里放了多少真实约束**。
- 负向回归的证据（退出码 + issue 列表）写进技能维护记录，不是一次性口头确认。

## 4. 独立包复编的四条判据

资源包必须能脱离原工作目录重建，且结果与交付物一致：

1. 解压到**另一个目录**。
2. 用**相同引擎**编译**三遍**（交叉引用需要多遍）。
3. 新 PDF 与交付 PDF **逐页逐像素相等**（渲染 `.samples` 逐字节比较）；页数相等。
4. **书签（`get_toc()`）相等**，并核对 TeX 源与资产的哈希。

只满足"能编译"不算通过。复编失败通常说明包内缺资产、路径写死、或字体依赖系统而非包内。

## 5. 缺陷归因：四层分开

同一个症状可能来自不同层，**归错层会导致错误修复**。

| 层 | 例子 | 处理 |
|---|---|---|
| 工具层 | 原生 PPTX 预览把内容放大约 1.5 倍（最小 5 矩形用例可复现）；同一 CLI 的 PDFium 分支正常 | 先最小复现隔离；换用真实导出的 PDF 独立渲染验证；**不要为迁就坏预览而缩放内容** |
| 生成层 | PDF pt 被乘 72/96；分式分母盒超出 viewBox；图区 bbox 裁掉曲线；展开式漏项 | 修生成逻辑；保持物理单位与完整对象边界 |
| 合同层 | 技能只给路由不给出渲染方法与终稿门禁，worker 自行补不可靠转换链 | 补可执行合同与门禁 |
| 监督层 | 明知图/数学损坏仍降低接受标准；对整体错位猜缓存；绕过资源门槛 | 隔离反馈工具；整体错位先最小复现；保留硬门槛 |

**工具缺陷与文档缺陷可以并存。** 修好其中一个不会自动修好另一个。历史上既证明了工具层 bug（最小复现），也证明了生成层 bug（独立渲染仍存在）。不能把所有问题归为"缓存"或"预览器"，也不能用工具 bug 掩盖自己的生成缺陷。

## 6. 资源约束（可执行条款）

本地重活（编译、渲染、OCR、大批量解压）在内存紧张时会中断或拖慢，导致失败重跑与产物不一致。

- **门槛**：空闲物理内存低于 **1 GiB** 时暂停本地重活。
- **测量**（Windows PowerShell）：

  ```powershell
  $os = Get-CimInstance Win32_OperatingSystem
  [math]::Round($os.FreePhysicalMemory / 1MB, 3)   # 单位 GiB
  ```

- **非破坏性回收**：只对白名单进程调用 `EmptyWorkingSet`（释放工作集，不杀进程），回收后复测。
- **保留名单**（绝不触碰）：当前 harness/agent 进程、编辑器与终端、VPN、SSH、安全软件、输入法、系统进程。
- **硬拦截**：未达门槛时中止重活并给出明确状态，例如 `throw 'Memory floor: paused'`；恢复后**串行**继续，不并发重跑。
- **禁止**：为通过 preflight 而修改/降低阈值；**禁止把降低后的阈值下发 worker**（历史事故：向 worker 传 `NF_RAM_FLOOR_MIB=560`）。
- **禁止**：为了过 gate 清空 `unresolved`、删掉未决项、或把阻塞观察降级为非阻塞。

## 7. 进度与止损

- 分别报告三个数字：**草稿覆盖**、**成功编译**、**已验收范围**。混成一个"进度"会误导。
- 外部 worker 必须有**可交付文件**才算通过；空返回不算通过，退出码 0 不算完成。
- 优先让主线**定期产生可检查的 PDF**，局部失败块单独修，不整书重译。
- 同类失败连续出现后，列清"假设 / 可区分实验 / 观察 / 反例"，把失败降到最小输入，确认反馈正确后再扩量。**不可用"花了很多时间"作为接受缺陷的理由。**
- 资源回收后如实记录本轮操作，不把它当作质量改进指标。

## 8. 验收报告必备字段

一份可复核的验收报告至少包含：

```json
{
  "artifact": "out/main.pdf",
  "pdf_sha256": "...", "tex_sha256": "...", "assets_sha256": "...",
  "source_sha256": "...", "source_pages_covered": "1-15",
  "pages_total": 15,
  "stage": "reviewed",
  "checks": {
    "build": {"engine": "xelatex", "passes": 3, "log_diagnostics": []},
    "technical": {"pass": true, "report": "qa/technical.json"},
    "typography": {"report": "qa/typo.md", "errors": 0, "warnings": 2},
    "visual": {"report": "qa/visual-review.json", "performed": true,
                "l1_pages": "1-15", "l2_pages": [1,3,5,6,8,10,11,13,15]},
    "independent_rebuild": {"pixel_identical": true, "toc_identical": true}
  },
  "size_check": {
    "source_pt": {"body": 9.96, "title": 14.35, "footer": 4.98},
    "output_pt": {"body": 9.46, "title": 14.2, "footer": 4.78},
    "max_deviation_pct": 4.8,
    "within_tolerance_3pct": false,
    "note": "数学与中文实测字号不同，需分别核对"
  },
  "issues": [],
  "unresolved": [],
  "limits": ["未恢复动画/备注", "第 2 页照片未评估印刷分辨率"]
}
```

- `limits` 必填。不写未覆盖范围的报告视为不完整。
- `size_check` 是"声明值 ≠ 实测值"门禁的落点，见 [cover-and-geometry.md](cover-and-geometry.md) §4。
- 报告披露**真实范围**：哪些沿用旧审校、哪些本轮重新检查，不把继承证据称作重新逐字校对。
- 内容、原生表示、技术、排版、视觉、独立复编分别记录 `not_performed / partial / passed / failed` 和真实范围。某维度是 `partial` 或 `not_performed` 时，不能仅因另一维度通过就把整个授权范围标成 `reviewed`。已有历史报告用词冲突时保留历史事实，并在本轮报告明确解释，不追认不存在的检查。
- 术语/上下文/规则变化先修订受影响工作包；模板、封面、绘图或字体环境变化重建并使旧 PDF 审查失效。当前状态与失效规则见 [translation-orchestration.md](translation-orchestration.md)。

## 9. 实测踩坑（带彩色语义框的教材项目）

以下每条都在"Pearson 风格双栏教材 → 中文单栏 + 语义框"的 331 页项目里真实踩过，**不是推测**。

1. **引擎禁止 paragraph 块含 `tabular`/显示数学**，但语义框必须"整框一个块"，而框里常有表格和行间公式。
   做法：在 `project.preamble` 定义 `\nftab{列格式}{表体}`、`\nftabx{...}{...}`、`\nfdisp{...}`、`\nfaligndisp{...}`，由 worker 在框内用宏写。
   这些宏仅用于保留语义框的排版，不能把“不触发字面量检查”当作验收。展开后的数学与表格仍须按独立对象计入来源合同、期望数量、原生性检查和逐对象视觉核对；框外表格/公式继续使用 `kind:"table"` / `"equation"`。未能验证宏内对象时保持未决，不能靠隐藏命令过门禁。
2. **中文正文里的 `%` 必须转义**。`39%` 会把该行剩余部分（连 `\\` 与 `\midrule`）整行注释掉，下一行多出 `&`，报 `Extra alignment tab`，且报错行号指向**下一行**，极难定位。
   做法：合并前检查未转义 `%`，按其实际处于正文、注释、代码/逐字环境的上下文修正；TeX 合法行尾注释不能全局替换。修复后对照源内容并重编，避免把一条正则当作通用 TeX 解析器。
3. **字面量 `\n`、`\` 后接汉字、`\begin{tikzpicture}` 写两遍**（第二份的 `[选项]` 会变成正文）都只是 LaTeX 层面的低级错，但都会让 400+ 页的整书编译停住。
   做法：合并前统一正则修复 + 环境配对自检（itemize/enumerate/axis/tikzpicture/figure/tabular/tcolorbox）。
4. **`\shade`（渐变）会生成 Form XObject，被 `nf qa` 判为"runtime proxy 位图"而 release 失败**。扁平 `\fill`、条纹色带（多条细矩形）都是纯矢量，不产生该对象。封面设计要"炫"时用后者，不要用渐变色。
5. **pgfplots 默认按千分位格式化刻度**：年份 1964 会印成 `1,964`；数值轴还会自动缩放成 `0.5/1/1.5/2 ×10⁶`。
   做法：preamble 里统一 `\pgfplotsset{every axis/.append style={scaled x ticks=false, scaled y ticks=false, xticklabel style={/pgf/number format/1000 sep={}}, yticklabel style={/pgf/number format/1000 sep={,}}}}`。
6. **`check_typography.py` 的两类稳定误报**（逐页目检后确认可忽略，写进报告即可，不要为它改版面）：
   - 分式公式的分子/分母 bbox 交叠 → 报 `text_overlap`；
   - 白字压在彩色标题条上时按**框底色**取色 → 报 `text_obscured_by_fill` 且对比度 <2。
7. **`release` 要求 `review.json.issues` 为空**。把"已修/按设计接受"的记录留在项目报告与审核文档里，`review.json` 只放**未关闭缺陷**；否则会在最后一步被挡住。
8. **引擎的 1 GiB 内存门槛会逐页检查**，长书一次性 `prepare 1-331` 很容易在中途失败。做法：按 28–56 页分批 `prepare` 到临时项目，再合并 `packet/pages/*` 与 `packet.json` 索引（schema 与哈希算法同引擎）；所有引擎调用套"等空闲内存 ≥1250 MB 再跑、失败重试"的循环。
9. **运行时装在 `~/.cache` 下的 Python 可能被缓存回收**，表现为"文件存在但 PowerShell/cmd 报无法识别"。做法：把整套 Python 运行时复制到项目盘的稳定路径，并直接调用 `python <engine>/native_forge.py <cmd>`（`nf.cmd` 里硬编码的路径会失效）。
10. **exFAT 工作区的原子写会稳定失败**（`EISDIR`）：项目放 NTFS，成品再拷到 exFAT 交付盘。
