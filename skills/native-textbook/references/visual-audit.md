# 纯视觉审核

**"编译成功""检查脚本通过""模型说看过"三者不能互相替代。** 本页定义"真的用眼睛看过了"这一步：看什么、用多大倍数看、怎么记录、谁签字。

背景：本项目的历史失败里，绝大多数最终缺陷**都能被看图发现**，却因为没有这一步骤而交付——图只剩顶端、分母消失、矩阵顺序倒置、正文压进页脚、首行贴着标题条、页底过挤。自动检查能查到"越界、重叠、缺字、字号分布"，**查不到"挤不挤、空不空、齐不齐、读起来顺不顺"**。

规则：**没有实际看图，就只能报"未完成视觉核验"，不能报通过。**

## 1. 两级分辨率

同一批页面看两遍，用途不同。只用缩略图会漏掉缺失的分母和小下标；只用高倍大图会看不出整页节奏。**两遍都要做。**

### L1 — 接触表（每页节奏、留白、对齐）

- 每张接触表放 **6 页**（2 行 × 3 列），每页缩略图约 480 px 宽。
- 用途：空白页、浮动体位置、页底过挤、留白节奏、图文关系、对齐、页眉页码、孤行寡行。
- 必须看**全部输出页**，不能抽样。

### L2 — 高风险页放大（公式、图内标签、细节）

- 含公式/图/矩阵/表格/边注/封面的页，逐页放大。
- 倍数：PyMuPDF `Matrix(3,3)`（≈216 dpi）或 Poppler `-r 144`。**两种渲染器都用**（不同渲染器暴露不同问题）。
- 用途：分数分母、积分上下限、根号、矩阵括号与顺序、负号、图内标签、`ε`/`1/ε` 之类推理数据、图裁框。
- 高风险页的判定按**本次来源的真实风险**选，不固定首页/中页/尾页。历史实际覆盖示例：3×MuPDF 看第 3、4、5、6、8、10、11、13、15 页；Poppler 144 dpi 看第 1、2、7、9、12、14 页。

**注意源页与输出页的渲染倍数可以不同**：源页缩略图用于定位对象，输出页必须高倍看细节。不要用源页的清晰度标准判断输出页。

### 本技能自带对比示例

`assets/review-examples/` 里是三组同页对比（各 PNG **左=失败稿，右=合格稿**），可用来校准自己的眼睛：这些缺陷在 L1 缩略图上就该被看出来，不用等 L2。

| 示例 | 失败稿的表现 | 合格稿的表现 |
|---|---|---|
| [compare-p05-waveforms.png](../assets/review-examples/compare-p05-waveforms.png) | 五个面板的**曲线、轴线、标签几乎全部消失**，只剩几个竖直短线尖端；"矩形脉冲信号""正弦信号"图注悬在空白上 | 五条完整波形、三条带箭头的 `t` 轴、刻度 `0`/`1`/`a`/`b`、幅度 `a`、周期 `2π/ω` 标注、图注齐备 |
| [compare-p15-ode.png](../assets/review-examples/compare-p15-ode.png) | 积分限 `1/T` 渲染成 `1/2`（**分母丢失**）；ODE 为 `dv(t)/___ + v(t)/___ = 1/___`（**三个分母全缺**），分数线压在文字下方；δ 函数系数与括号错位；上下标与相邻字符挤在一起 | `∫_{-1}^{2}(...)dt` 完整；`dv(t)/dt + v(t)/R = 1/R` 完整清晰；下标与运算符间距正常 |
| [compare-p03-matrix.png](../assets/review-examples/compare-p03-matrix.png) | 向量矩阵的括号与元素错位、不成矩阵 | 矩阵括号完整、元素各行对齐、`v = [v1 v2 v3]^T` 正确 |

这三组正是"分母消失""图只剩顶端""矩阵顺序倒置"三种典型症状。**它们在最终 PDF 里都存在，独立渲染也无法解释为预览器问题**——所以只能靠看图抓出来。

L1 就能看出第 5 页的图没了、字号整体偏小；L2 才能看出第 15 页分母缺失。这就是为什么要做两级。

## 2. 逐对象核对清单

看图时按对象类型逐项核对，**不是"整体看着还行"**。

### 正文
- 每段首尾完整，没有被切掉半句；跨页续段读得通
- 段落顺序与源一致；没有重复段、漏段
- 中文标点全角；行首没有出现行首禁则标点（，。、）等）
- 行末没有大空洞（两端对齐把某行拉散）
- 缩进一致；段间距一致

### 数学（逐式，不能只看"这页有公式"）
- 每个分式的**分子和分母都在**（历史缺陷：分母被裁掉）
- 积分/求和/连乘的**上下限完整**，含负号
- 根号覆盖范围正确
- 矩阵的**括号完整、行序正确、列数正确**
- 下标上标层级正确，没有被压平
- 公式编号与源一致；编号没有被排到纸外
- 展开式的**最后一项未丢失**（即使该项最终为 0）
- 句末标点在公式内；没有多余逗号（`\,` 被当成字符）

### 图
- 轴线、箭头、刻度、图题都在；曲线**完整**（没有只剩顶端/半个周期）
- 图内标签齐全且不重叠、不压线
- `ε`、`2ε`、`1/ε` 等在的推理数据没有缺
- 图与图注同页
- 图内字号读得清

### 表格
- 每个单元格内容与源一致；空单元格是源本来就是空的
- 列数、列对齐正确；跨页表有重复表头
- 线框/三线表样式一致

### 边注/脚注
- 注号与正文标记在同一页；注号没有独占一行
- 注文完整，没有被图打断叙述
- 注与相关图/正文没有互相穿插

### 页面级
- 正文没有伸进页脚保留区
- 首个正文对象与标题带之间有空隙（历史缺陷：贴着标题条）
- 页底不过挤；没有孤零零的尾行
- 页眉/页码正确且与当前章一致
- **没有"近空白页"**：实测成熟成品也存在孤儿行造成的近空白页——倒数第二行被推到下一页、或上页末尾只剩一两行。发现后调 `\widowpenalty`/`\clubpenalty` 或改写该段
- **同一推导的公式没有被分页切断**（实测成熟成品 28 处相邻页都以公式行结束/开始）
- **上下标脚注标记没有与相邻文字碰撞**（实测成熟成品的真实缺陷：上标注号压到前一个字）
- 同页内垂直间距一致；没有因公式撑开造成的忽紧忽松

### 封面
- 主标题、副标题、作者/机构/日期位置正确
- 没有空标题带（源无标题的页不画带）
- 源"标题被图遮住"的页：如实登记，不补造
- 封面留白比例是有意图的，不是"内容太少"

## 3. 审查记录（必须绑定指纹）

审查记录必须绑定**当前交付 PDF 的哈希**，并列出实际看过的页、用的方法、发现的问题。旧 PDF 的审查不能用于新 PDF。

```json
{
  "artifact": "项目/build/main.pdf",
  "pdf_sha256": "<当前交付 PDF 的 sha256>",
  "tex_sha256": "<TeX 源 sha256>",
  "rendered_at": "2026-10-14T15:00:00+08:00",
  "reviewer": "<角色名>",
  "scope": {
    "pages_total": 15,
    "l1_contact_sheets_pages": "1-15",
    "l2_hi_res_pages": [1, 3, 5, 6, 8, 10, 11, 13, 15],
    "l1_tool": "PyMuPDF 1x thumbnails 480px, 6 per sheet",
    "l2_tools": ["PyMuPDF Matrix(3,3)", "Poppler -r 144"],
    "source_reference_pages": {"out": {"1": "src 1", "3": "src 3"}}
  },
  "reviewed_objects": [
    {"page": 6, "kind": "equation", "id": "p6-eq-rms", "checked": "分子分母、积分上下限、1/T 外层 1/2", "verdict": "pass"},
    {"page": 11, "kind": "equation", "id": "p11-expansion", "checked": "展开式 4 项含最后一项", "verdict": "fail", "issue": "第 4 项缺失"}
  ],
  "issues": [
    {"severity": "error", "page": 11, "object": "p11-expansion",
     "symptom": "展开式漏最后一项", "evidence": "evidence/p11-mupdf3x.png",
     "action": "补回该项并重新渲染"}
  ],
  "limits": [
    "未核对动画/备注（来源为静态 PDF，不恢复交互）",
    "第 2 页图为真实照片，未评估其分辨率是否够印刷"
  ],
  "visual_review": "performed",
  "semantic_review": "performed"
}
```

要求：

- `pdf_sha256` 必填；与当前文件不符即视为该审查**失效**。
- `reviewed_objects` 列出**逐个核对过的具体对象**（不是"看过第 6 页"）；每个对象写"查了什么"。
- `limits` 必须写**没检查什么**。不写 limits 的审查记录视为不可信。
- `visual_review` / `semantic_review` 只能是 `performed` / `not_performed`。**没有实际看图就填 `not_performed`**，与 `check_slide_pdf.py` 的默认输出一致，不得预填 `performed`。

## 4. 双角色：监工全页 + 独立审查高风险子集

- **监工**：看**全部**输出页（L1 全页 + L2 高风险页），并对授权源页做对照。
- **独立审查**：由未参与制作的审查者，对**高风险子集**再独立看一遍，逐项核对公式/图/边界；不复制监工的清单，独立出结论。
- **不得代签**：worker 不能预填通过的审查结论；制作人不能替审查者签字。
- 两个角色的记录分开存，结论不一致时**以实际看图证据为准**，冲突项升级处理而不是折中。
- 独立审查至少覆盖：所有含高风险公式的页、所有被裁/重绘过的图所在页、封面、以及本次新增或修改的页。

## 5. 证据继承的严格条件

- 修改后产生**新 hash**，旧审查**全部失效**。
- 只有**像素完全一致**的页面才能继承旧审查证据；必须逐页比较渲染后的 `.samples` 字节相等，并记录"继承自哪个哈希"。
- 历史实例：定稿后只改了空标题页的灰带和 PDF 书签，其余页渲染哈希不变，因此其余页继承已看图证据，而空标题页用最新的 Poppler 图**重新检查**。
- 不能因为"只改了一个字"就假定版式没变——改字会推挤后续分页。

## 6. 渲染与检查工具

### 6.1 生成接触表与高风险页图

```powershell
# 全页缩略接触表（每张 6 页）+ 高风险页高倍图
python scripts/render_review_sheets.py --pdf "项目\build\main.pdf" `
  --out "项目\qa\review" --sheet-pages 6 --thumb-width 480 `
  --hi-res-pages "1,3,5,6,8,10,11,13,15" --hi-res-zoom 3

# 独立渲染器交叉核对（Poppler）
pdftoppm -r 144 -png "项目\build\main.pdf" "项目\qa\review\poppler-144"
```

输出 `contact-01.png`（第 1–6 页）等接触表和各页高倍 PNG；`manifest.json` 记录输入 PDF 的 sha256、页数、每页 PNG 的 sha256、缩放倍数与工具。**审查证据绑定这些哈希。**

### 6.2 排版几何检查（先跑，缩小看图范围）

```powershell
python scripts/check_typography.py --pdf "项目\build\main.pdf" --mode book `
  --out "项目\qa\typo.json" --report "项目\qa\typo.md"
```

它给的是几何事实（越界、文字与填充重叠、不可见文字、字号分布、按字号的基础行距、行末填充率、版心留白），用来**定位**要重点看哪几页。它**不证明**页面好看。

### 6.3 技术检查（另有专门脚本）

课件走 `scripts/check_slide_pdf.py`（页数/尺寸/栅格图/字体嵌入/越界/必需字符）。注意它自己声明的边界：文字存在与 bbox **不证明**数学或翻译正确；bbox **查不到**所有裁切/遮挡/重叠；图片计数**不证明**矢量来源；字体嵌入**不证明**字形可见性。它把 `visual_review` 固定写成 `not_performed`，等本页的审查来填。

**检查器效力必须以负向回归证明**：把已知有缺陷的旧稿拿来跑，必须失败；把它配上项目内容合同与不给内容合同两种情况分别跑，观察差别。历史实测：旧 Signals 差稿在同一份项目合同下报 5 项失败，但在"基础检查"下 0 issues 通过——**说明"通过"含义完全取决于配置里放了多少真实约束**。

## 7. 看图时容易漏的地方

- 缩略图看不出小下标、丢失的分母、断开的箭头 → 必须 L2。
- 高倍图看不出页底过挤、留白不均、浮动体落到无关位置 → 必须 L1。
- 只看渲染器的默认渲染会漏掉**渲染器差异**：同一 PDF 用两个渲染器都看。
- 只看自己生成的检查器输出会**继承检查器的盲区**（bbox 查不到遮挡）。
- "整体看着不错"不是核对。必须按第 2 节逐对象过。
- **工具缺陷与文档缺陷可以并存**：反馈工具坏了（例如原生 PPTX 预览比例错误）不等于文档没错。先用四边标记/最小矩形样张校准反馈工具，再对比真实导出的 PDF；**不能靠整体缩放/移动内容去迁就未校准的预览器**。
